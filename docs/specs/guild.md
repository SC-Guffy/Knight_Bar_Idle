## 규칙

### 1. 구조
- **기사단** = 이름(2~12자, 전 서버 중복 불가) · Google 계정 · 슬롯 · 공용 상태(마을·공용 재화).
- **기사** = 지금의 계정 하나와 같다. 닉네임(전 서버 중복 불가, 랭킹·결투·레이드에 쓰임)·직업·레벨·장비·스킬·훈련·입장권·스태미나·진행 상태를 각자 갖는다.
- **보유 기사**는 최대 10명. **슬롯**(동시에 굴리는 자리)은 2~5칸. 슬롯에 없는 기사는 멈춰 있고(진행 없음) 기사단 효과에만 기여한다. 슬롯 배정은 캠프 안에서만 바꾼다(콘텐츠 진행 중인 기사는 못 뺀다).
- 처음: 기사단 이름 짓기 → 첫 기사 닉네임 → 바로 게임. 두 번째 기사는 슬롯 2에서 "새 기사"로 만든다.

### 3. 동시 진행 (모든 기사가 독립적으로 돈다)
- 서버가 싸움을 계산하는 콘텐츠(레이드·결투·월드 보스·교관 승부)는 결과만 받으면 된다. 안 보고 있는 기사는 **재생을 건너뛰고 바로 정산**하고, 슬롯 칩에 결과 점(●)을 띄운다. 레이드 대기방은 기사마다 따로 들어가고 준비 상태도 각자 유지한다.
- 실시간 콘텐츠(원정·탑·미궁·성벽)는 지금 `src/world.js` 한 벌의 전역 상태(`monsters`·`knight`·`tw`·`dv`…)와 `S` 하나로 돈다. 동시 진행 방법은 **1단계 기술 검증**에서 정한다:
  - **후보 ① 기사마다 숨은 iframe** (추천 시작안): 같은 게임 코드를 기사 수만큼 같은 주소의 iframe 으로 띄운다. 전역 상태가 저절로 나뉘어 world.js 를 고치지 않는다. 바깥 페이지가 매 프레임 각 iframe 의 `update(dt)` 를 부르고, 화면은 보고 있는 기사만 그린다(나머지는 그리기 건너뜀). 슬롯 전환 = 그 iframe 을 보이게 = 새로 고침 없음. 공용 재화는 바깥 페이지의 객체 하나를 각 `S` 에 getter/setter 로 걸어 같이 쓴다(같은 origin 이라 동기 접근 가능).
  - 후보 ② world.js 를 "기사마다 월드 한 벌" 객체로 고친다: 정확하지만 3,000줄 넘는 리팩터링.
  - 후보 ③ 안 보는 기사의 탑·미궁·성벽은 근사 계산: 싸게 되지만 직접 볼 때와 결과가 달라진다 → 쓰지 않는다.
- 앱(브라우저 탭)을 완전히 끄면 지금처럼 모든 기사가 오프라인 규칙을 따른다 (원정만 시뮬, 탑·미궁·성벽은 그 자리에서 정산).
- 한 기사단은 **한 기기에서만** 돈다. 다른 기기에서 로그인하면 먼저 기기에 "다른 기기에서 접속했어요"를 띄우고 멈춘다(세이브는 지금처럼 클라이언트 덮어쓰기라 두 기기가 동시에 쓰면 꼬인다).

### 4. 슬롯과 기사단 회관
- 새 마을 건물 **🛡️ 기사단 회관** (공용 마을 건물, 안 B 면 기사단 상태에 따로 둔다). Lv1 슬롯 2 · Lv3 슬롯 3 · Lv6 슬롯 4 · Lv10 슬롯 5 (시작안, 진행 봇으로 연다는 시점 확인). 비용은 다른 건물 곡선(`buildCost`)에 배율.
- 회관 Lv 은 기사단 효과 최대치(아래 ⑤)도 연다.

### 5. 기사단 효과 (수치는 시작안 — 진행 봇으로 확정)
직업 특성으로 밸런스 원칙([class-identity-balance]) 에 맞춰 **콘텐츠 전용 보정은 넣지 않는다**. 모두 기본 능력치.
- **계열 효과**: 1차 계열마다 그 계열 최고 레벨 기사 1명만 센다(같은 계열 여러 명은 겹치지 않음 → 이것저것 키우게).
  | 계열 | 효과 (기사단 전원) |
  |---|---|
  | ⚔️ 검사 | 공격력 |
  | 🔱 창기사 | 최대 체력 |
  | 🏹 레인저 | 치명타 확률 |
  | 🪄 마법사 | 스킬 피해 |
  | 🥊 파이터 | 공격 속도 |
  | 🗡️ 암살자 (시즌7 신규) | 치명타 피해 |
  - 크기: 기사 레벨 20마다 +1단, 단당 +1% (시작안), 최대 단은 회관 Lv 로 제한.
- **다양성 효과**: Lv 50 이상 기사가 있는 계열 수 n → 모든 피해 +n% (시작안).
- **따라잡기**: 새 기사는 기사단 최고 레벨의 80% 까지 경험치 ×2 (시작안). 부캐 키우기가 처음부터 다시 하는 지루함이 되지 않게.
- 목표 크기: 6계열을 다 키운 기사단의 본캐 전투력이 본캐 하나만 키운 경우보다 약 +15~20%.

### 6. 랭킹·결투·레이드·월드 보스
- 기사마다 따로 순위에 오른다. 이름 옆에 작게 기사단 이름.
- 같은 기사단 기사끼리 레이드 파티 허용(사용자 6번). 결투는 같은 기사단끼리 못 건다(점수 짜고 치기 막기).
- 월드 보스 시도·보상도 기사마다 따로.
- AI 기사(봇)는 기사단 없이 지금 그대로.

### 7. 로그인 (Google)
- 웹(GitHub Pages·로컬): Google Identity Services 버튼 → ID 토큰 → 서버 `POST /api/auth/google` 이 검증(Google 공개키, `aud` = 우리 클라이언트 ID) → 기사단 토큰 발급. 기사단이 없으면 이름 짓기로.
- Electron 앱: Google 이 앱 안 로그인 창을 막고, `preload.js` 에 외부 브라우저 열기가 없다. 그래서 **연결 코드**: 앱에 6자리 코드(10분) → 사용자가 아무 브라우저에서 게임 웹 주소의 "기기 연결" 로 Google 로그인 후 코드 입력 → 앱이 폴링으로 토큰을 받는다. main.js·preload.js 를 안 바꿔서 **재설치 없음**. 게임 모음 사이트 iframe 안에서 Google 버튼이 막히면 같은 연결 코드로.
- 서버 준비물: Google Cloud OAuth 클라이언트 ID (승인된 JavaScript 원본: GitHub Pages 주소·localhost 포트들). 클라이언트 ID 는 공개값이라 코드에 넣어도 된다. 비밀키는 쓰지 않는다(ID 토큰 검증만).
- 저장: `guilds` = { id, name, nameKey, googleSub, tokenHash, state(공용), slots, createdAt, updatedAt }. 기사(지금 `accounts` 행)에 `guildId`·`slot` 추가. 요청은 기사단 토큰 + `X-Char: <기사 key>` 헤더, 서버가 소속을 확인.

## UI
- HUD 위 왼쪽에 슬롯 칩 1~5 (사용자 그림 위치). 칩 = 직업 도트 아이콘 + Lv + 지금 하는 일 작은 표시(원정·탑·미궁·성벽·레이드·캠프). 보고 있는 칩은 밝게, 할 일(원정 보고·레이드 결과·입장권 남음)이 있으면 레드닷. 잠긴 칩은 자물쇠, 누르면 회관 안내.
- 크고 투박한 박스 금지, 칩 한 줄. 좁은 창에서 잘리지 않는지 확인.
- 캠프 → 마을 탭에 🛡️ 기사단 회관: 보유 기사 목록·슬롯 배정·계열 효과 표·새 기사.
