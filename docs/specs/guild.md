## 목표
- 한 사람이 **기사단** 하나 안에서 기사(캐릭터) 여러 명을 키운다. 이것저것 키울수록 기사단 전체가 강해진다.
- 슬롯을 누르면 그 기사 화면으로 **바로** 바뀐다. 한 기사는 원정, 한 기사는 레이드, 한 기사는 탑 — **모든 기사가 동시에 독립적으로 돈다** (사용자, 10-16: "다 가능하게 하는 게 목표").

## 규칙

### 1. 구조
- **기사단** = 이름(2~12자, 전 서버 중복 불가) · Google 계정 · 슬롯 · 공용 상태(마을·공용 재화).
- **기사** = 지금의 계정 하나와 같다. 닉네임(전 서버 중복 불가, 랭킹·결투·레이드에 쓰임)·직업·레벨·장비·스킬·훈련·입장권·스태미나·진행 상태를 각자 갖는다.
- **보유 기사**는 최대 10명. **슬롯**(동시에 굴리는 자리)은 2~5칸. 슬롯에 없는 기사는 멈춰 있고(진행 없음) 기사단 효과에만 기여한다. 슬롯 배정은 캠프 안에서만 바꾼다(콘텐츠 진행 중인 기사는 못 뺀다).
- 처음: 기사단 이름 짓기 → 첫 기사 닉네임 → 바로 게임. 두 번째 기사는 슬롯 2에서 "새 기사"로 만든다.

### 3. 동시 진행 (모든 기사가 독립적으로 돈다)
- 서버가 싸움을 계산하는 콘텐츠(레이드·결투·월드 보스·교관 승부)는 결과만 받으면 된다. 안 보고 있는 기사는 **재생을 건너뛰고 바로 정산**하고, 슬롯 칩에 결과 점(●)을 띄운다. 레이드 대기방은 기사마다 따로 들어가고 준비 상태도 각자 유지한다.
- 실시간 콘텐츠(원정·탑·미궁·성벽)는 지금 `src/world.js` 한 벌의 전역 상태(`monsters`·`knight`·`tw`·`dv`…)와 `S` 하나로 돈다. 동시 진행 방법은 **1단계 기술 검증**에서 정한다:
  - **후보 ① 기사마다 숨은 iframe** (추천 시작안): 같은 게임 코드를 기사 수만큼 같은 주소의 iframe 으로 띄운다. 전역 상태가 저절로 나뉘어 world.js 를 고치지 않는다. 바깥 페이지가 매 프레임 각 iframe 의 `update(dt)` 를 부르고, 화면은 보고 있는 기사만 그린다(나머지는 그리기 건너뜀). 슬롯 전환 = 그 iframe 을 보이게 = 새로 고침 없음. 공용 재화는 바깥 페이지의 객체 하나를 각 `S` 에 getter/setter 로 걸어 같이 쓴다(같은 origin 이라 동기 접근 가능).
  - 후보 ② world.js 를 "기사마다 월드 한 벌" 객체로 고친다: 정확하지만 3,000줄 넘는 리팩터링.
  - 후보 ③ 안 보는 기사의 탑·미궁·성벽은 근사 계산: 싸게 되지만 직접 볼 때와 결과가 달라진다 → 쓰지 않는다.
- 앱(브라우저 탭)을 완전히 끄면 지금처럼 모든 기사가 오프라인 규칙을 따른다 (원정만 시뮬, 탑·미궁·성벽은 그 자리에서 정산).
- 한 기사단은 **한 기기에서만** 돈다. 다른 기기에서 로그인하면 먼저 기기에 "다른 기기에서 접속했어요"를 띄우고 멈춘다(세이브는 지금처럼 클라이언트 덮어쓰기라 두 기기가 동시에 쓰면 꼬인다).

### 4. 슬롯과 기사단 회관
- 새 마을 건물 **🛡️ 기사단 회관** (공용 마을 건물, 안 B 면 기사단 상태에 따로 둔다). Lv1 슬롯 2 · Lv3 슬롯 3 · Lv6 슬롯 4 · Lv10 슬롯 5 (시작안, 진행 봇으로 연다는 시점 확인). 비용은 다른 건물 곡선(`buildCost`)에 배율.
- 회관 Lv 은 기사단 효과 최대치(아래 ⑤)도 연다.

### 5. 기사단 효과 (4단계에서 확정 — 아래 "4단계" 절의 확정 수치가 기준)
직업 특성으로 밸런스 원칙([class-identity-balance]) 에 맞춰 **콘텐츠 전용 보정은 넣지 않는다**. 모두 기본 능력치.
- **계열 효과**: 1차 계열마다 그 계열 최고 레벨 기사 1명만 센다(같은 계열 여러 명은 겹치지 않음 → 이것저것 키우게).
  | 계열 | 효과 (기사단 전원) |
  |---|---|
  | ⚔️ 검사 | 공격력 |
  | 🔱 창기사 | 최대 체력 |
  | 🏹 레인저 | 치명타 확률 |
  | 🪄 마법사 | 스킬 피해 |
  | 🥊 파이터 | 공격 속도 |
  | 🗡️ 암살자 (시즌7 신규) | 치명타 피해 |
  - 크기: 기사 레벨 20마다 +1단, 단당 +1% (시작안), 최대 단은 회관 Lv 로 제한.
- **다양성 효과**: Lv 50 이상 기사가 있는 계열 수 n → 모든 피해 +n% (시작안).
- **따라잡기**: 새 기사는 기사단 최고 레벨의 80% 까지 경험치 ×2 (시작안). 부캐 키우기가 처음부터 다시 하는 지루함이 되지 않게.
- 목표 크기: 6계열을 다 키운 기사단의 본캐 전투력이 본캐 하나만 키운 경우보다 약 +15~20%.

### 6. 랭킹·결투·레이드·월드 보스
- 기사마다 따로 순위에 오른다. 이름 옆에 작게 기사단 이름.
- 같은 기사단 기사끼리 레이드 파티 허용(사용자 6번). 결투는 같은 기사단끼리 못 건다(점수 짜고 치기 막기).
- 월드 보스 시도·보상도 기사마다 따로.
- AI 기사(봇)는 기사단 없이 지금 그대로.

### 7. 로그인 (Google)
- 웹(GitHub Pages·로컬): Google Identity Services 버튼 → ID 토큰 → 서버 `POST /api/auth/google` 이 검증(Google 공개키, `aud` = 우리 클라이언트 ID) → 기사단 토큰 발급. 기사단이 없으면 이름 짓기로.
- Electron 앱: Google 이 앱 안 로그인 창을 막고, `preload.js` 에 외부 브라우저 열기가 없다. 그래서 **연결 코드**: 앱에 6자리 코드(10분) → 사용자가 아무 브라우저에서 게임 웹 주소의 "기기 연결" 로 Google 로그인 후 코드 입력 → 앱이 폴링으로 토큰을 받는다. main.js·preload.js 를 안 바꿔서 **재설치 없음**. 게임 모음 사이트 iframe 안에서 Google 버튼이 막히면 같은 연결 코드로.
- 서버 준비물: Google Cloud OAuth 클라이언트 ID (승인된 JavaScript 원본: GitHub Pages 주소·localhost 포트들). 클라이언트 ID 는 공개값이라 코드에 넣어도 된다. 비밀키는 쓰지 않는다(ID 토큰 검증만).
- 저장: `guilds` = { id, name, nameKey, googleSub, tokenHash, state(공용), slots, createdAt, updatedAt }. 기사(지금 `accounts` 행)에 `guildId`·`slot` 추가. 요청은 기사단 토큰 + `X-Char: <기사 key>` 헤더, 서버가 소속을 확인.

## UI
- **HUD 바로 위에 작은 숫자 버튼 1 2 3 4 5 한 줄** (사용자, 10-16: 화면 왼쪽 위가 아니라 HUD 위에 작게). 버튼엔 숫자만, **버튼 바로 위에 지금 하는 일을 작은 아이콘 하나로**(⚔️ 원정 · ↩️ 귀환 · 🗼 탑 · 🎰 미궁 · 🏰 성벽 · 🐉 레이드 · ⛺ 캠프, 게임 도트 아이콘이 있으면 그걸로 — 글자 없음, 사용자 10-16). 보고 있는 기사는 밝게, 할 일(원정 보고·탑/미궁/성벽 끝남·레이드 결과·입장권 남음)이 있으면 레드닷, 잠긴 칸은 자물쇠(누르면 회관 안내). 빈 칸(열렸지만 기사 없음)은 흐린 숫자, 누르면 회관의 새 기사·배정.

- 크고 투박한 박스 금지. 버튼 크기는 HUD 글자 높이 정도. 좁은 창에서 HUD·버튼을 가리거나 잘리지 않는지 확인.
- 캠프 → 마을 탭에 🛡️ 기사단 회관: 보유 기사 목록·슬롯 배정·계열 효과 표·새 기사.

## 1단계 본 구현 — 이 기기 안 기사단 (구현됨 · 사용자 확인 2026-10-17)
사용자 결정(10-16): **화면 먼저**. 서버·Google 로그인 없이, 지금 계정(닉네임 토큰)들을 이 기기 안에서 기사단으로 묶어 슬롯 칩·회관·공용 마을을 먼저 만들고 직접 굴려 본다. 서버 기사단·Google 은 2단계(Google Cloud OAuth 클라이언트는 그동안 사용자가 만든다).

### 켜는 법 · 구조
- `index.html` 이 맨 위 창이고 기사단 모드가 켜져 있으면(`?guild=1` 로 켜면 localStorage `knight-bar-guild-on` 에 남고, `?guild=0` 으로 끈다) **기사단 호스트 `guild.html`**(+ `src/guild.js`)로 넘어간다. 호스트가 슬롯마다 `index.html?char=닉네임` iframe 을 만든다 — 시제품 `dev/guild-spike.html` 을 게임 안으로 옮긴 것. main.js·preload.js 는 안 바꾼다.
- 시제품 오른쪽 위 측정판(fps·ms·JS 힙·시험 상태 넣기)은 `dev/guild-spike.html` 전용 테스트 도구다. 본 구현 게임 화면에는 넣지 않는다.
- 시즌7 을 열기 전까지는 **꺼져 있음**(플래그로만 켬) → 1단계를 main 에 올려도 지금 플레이어에겐 안 보인다. 시즌7 오픈 때 기본값을 켠다.
- 기사 = 지금 계정 그대로(세이브 키 `knight-bar-save-v1:<닉네임>` 그대로). 새 기사 = 지금 닉네임 만들기(`POST /api/accounts`) 그대로 → 서버는 1단계에서 안 바꾼다. 같은 기사단끼리 결투 금지는 서버가 기사단을 알게 되는 2단계에서.
- **1단계는 웹만** (구현 중 변경, 10-17): Electron 창은 클릭 통과(`setIgnoreMouseEvents`)·창 크기 요청(`bar.setWindow`)·계정/flush 콜백을 iframe 한 개 기준으로 주고받는다. iframe 5개가 같은 `bar` 를 쓰면 숨은 기사가 창 크기·클릭 영역을 바꿔 버린다 → 보이는 기사 하나만 `bar` 를 쓰게 중계하는 일은 앱에서 직접 돌려 봐야 해서, Google 연결 코드와 함께 2단계에서 한다. 지금은 `window.bar` 가 있으면 기사단 플래그를 무시하고 보통 게임으로 돈다.

## 2단계 — 서버 기사단 · Google 로그인 · 연결 코드 · Electron (구현됨 · 진짜 Google 은 클라이언트 ID 대기)
1단계(이 기기 안 기사단)를 서버로 올려, 어느 기기에서든 Google 로그인 한 번으로 내 기사단·기사들을 이어 한다. 공용 상태(마을·재화)를 서버에 저장하는 건 3단계 — 2단계에서 공용 상태는 아직 기기에 있다.

### 서버 저장
- 새 표 `guilds` = `{ id, name, nameKey(소문자, 전 서버 중복 불가), googleSub(Google 계정 고유 번호, 중복 불가), tokenHash, deviceId, chars: [기사 key…], slots: [기사 key|null × 5], createdAt, updatedAt }`. 파일 저장소(`DATA_DIR/guilds.json`)·Postgres 둘 다.
- 기사(지금 `accounts` 행)에 `guildId` 를 더한다. 기사단 소속 기사는 개인 토큰이 없다(아무도 모르는 무작위 해시 — AI 기사처럼).
- 이메일·이름·사진 같은 Google 개인정보는 저장하지 않는다. `sub`(숫자 ID)만.

### 인증
- 기사단 토큰 하나로 소속 기사 누구든 움직인다: `Authorization: Bearer <기사단 토큰>` + `X-Char: <닉네임>`. 서버 `auth()` 가 기사단 토큰이면 `X-Char` 기사가 그 기사단 소속인지 확인하고 그 기사 행을 돌려준다 → 지금 있는 API(세이브·결투·레이드·탑·월드 보스…)는 **안 고친다**.
- 개인 토큰(지금 방식)도 그대로 받는다 — 시즌7 전까지는 둘 다.

### Google 로그인 (웹)
- 화면: 기사단 모드 첫 화면에 **Google 로 시작** 버튼(Google Identity Services, `accounts.google.com/gsi/client`). 버튼 → Google 이 ID 토큰(JWT)을 준다 → `POST /api/auth/google { idToken }`.
- 서버 검증: Google `tokeninfo` 로 서명·만료 확인, `aud` = 우리 클라이언트 ID(`GOOGLE_CLIENT_ID` 환경 변수), `iss` = accounts.google.com. 비밀키는 쓰지 않는다.
- 응답: 그 `sub` 의 기사단이 있으면 `{ token, guild }`, 없으면 `{ token, guild: null }` → 기사단 이름 짓기 `POST /api/guilds { name }` → 첫 기사 닉네임 `POST /api/guilds/chars { nickname, state, profile }`.
- 로그인할 때마다 토큰을 새로 발급한다(예전 토큰은 무효). 토큰은 localStorage `knight-bar-guild-token`. 예전 토큰을 들고 있던 기기는 다음 요청에서 401 `guild-auth` → "다른 기기에서 다시 로그인했어요 — [다시 로그인]" 안내 (구현 중 정함, 10-17).
- CSP: `index.html`·`guild.html` 에 `script-src https://accounts.google.com/gsi/client` · `frame-src https://accounts.google.com` · `connect-src` 에 같은 주소를 더한다.
- 개발용: 서버 `GOOGLE_FAKE=1` 이면 `fake:<sub>` 를 ID 토큰으로 받는다(로컬 테스트·자동 검증용, 배포 서버엔 안 켠다).

### 연결 코드 (Electron 앱 · Google 버튼이 막힌 곳)
- Google 은 앱 안 로그인 창을 막고, 게임 모음 사이트 iframe 안에서도 버튼이 막힐 수 있다.
- 앱: "기기 연결" → `POST /api/link/start` → 6자리 숫자 코드(10분) → 화면에 코드와 "게임 웹 주소에서 이 코드를 넣어 주세요" 안내 → 3초마다 `GET /api/link/poll?id=…`.
- 사용자: 아무 브라우저에서 게임 웹 주소 → Google 로그인 → "기기 연결" 에 코드 입력 → `POST /api/link/confirm { code }` (기사단 토큰으로).
- 앱 폴링이 기사단 토큰을 받는다 → 바로 기사단으로. main.js·preload.js 를 안 바꾸므로 **앱 재설치 없음**.
- 코드는 한 번만 쓰고, 틀린 코드 5번이면 그 코드를 버린다.

### 한 기사단은 한 기기에서만
- 로그인(또는 연결 코드)할 때 기기 번호(`deviceId`, 기기 localStorage 의 무작위 값)를 기사단에 적는다. 요청마다 `X-Device` 를 보내고, 서버의 `deviceId` 와 다르면 `409 { code: 'moved' }`.
- 먼저 기기는 409 를 받으면 저장을 멈추고 "다른 기기에서 접속했어요 — 여기서 다시 하려면 [이 기기에서 계속]" 을 띄운다. 누르면 다시 로그인한 것처럼 이 기기로 가져온다.
- 두 경우가 있다: 연결 코드·"이 기기에서 계속" 은 토큰은 같고 기기만 바뀐다 → 409 `moved` → [이 기기에서 계속]. Google 로 다른 기기에서 다시 로그인하면 토큰이 바뀐다 → 401 `guild-auth` → [다시 로그인].

### Electron 에서 기사단 (1단계에서 미룬 것)
- 앱 창 API(`window.bar`)를 바깥 페이지가 **중계**한다: iframe 의 게임은 `window.bar` 대신 바깥이 준 대리 객체를 쓴다.
  - 보는 기사만 실제로 보낸다: `setWindow`·`setInteractive`·`setCampMode`·`setOverlay`·`setTrayTitle`·`setAccount`. 숨은 기사의 요청은 기억만 해 두고, 그 기사로 바꾸는 순간 앞 기사의 요청을 거두고 새 기사의 것을 보낸다.
  - 앱 → 게임 신호는 바깥이 나눠 준다: `onFlush`(모든 기사 저장·서버 올리기 뒤 한 번만 `flushed`), `onSettings`·`onDisplay`(모두), `onReset`(보는 기사만), `onSwitchAccount`(보는 기사의 회관 열기).
  - 슬롯 버튼 위에 마우스가 오면 바깥 페이지가 직접 `setInteractive(true)`.
- 앱을 실제로 띄우지 않는 규칙대로, 가짜 `bar`(호출 기록만 하는 객체)를 웹에서 넣어 중계 규칙을 확인한다. 앱 실기 확인은 사용자에게 맡긴다.

## 3단계 — 공용 상태 서버 저장 (구현됨 · 사용자 확인 대기)
2단계까지 공용 상태(🪙 골드 · 🪵 목재 · 🪨 철광석 · 마을 건물 · 창고 비축/교역 · 대장간 시설 · 건설)는 **그 기기 localStorage**(`knight-bar-guild` 의 `shared`)에만 있다. 그래서 다른 기기에서 로그인하면 기사는 같아도 마을·골드가 비어 있다. 3단계에서 이걸 서버 기사단에 저장해 **어느 기기에서든 같은 마을**로 이어 한다.

### 서버 저장
- `guilds` 에 `shared`(공용 상태 JSON) · `sharedRev`(저장할 때마다 +1) · `sharedAt`(그 저장의 **서버 시각**) 을 더한다. 파일·Postgres 둘 다.
- `GET /api/guilds/me` 응답에 `shared`·`sharedRev`·`sharedAt` 을 같이 준다.
- `PUT /api/guilds/shared { shared, rev }` — 기사단 토큰 + `X-Device`(다른 기기면 409 moved, 2단계 그대로). `rev` 가 서버 것과 다르면 409 `stale` + 서버 쪽 공용 상태를 돌려준다(옛 기기가 새 기록을 덮어쓰지 못하게). 맞으면 저장하고 `sharedRev+1`, `sharedAt = 지금 서버 시각`.
- 서버는 모양만 검사한다: 아는 키만 받고, 숫자는 유한·0 이상, 건물 Lv 은 1~최대 정수, 크기 상한(16 KB). 값의 정당성은 지금 기사 세이브처럼 클라이언트를 믿고 **운영 기록**으로 본다: 한 시간마다 공용 재화 스냅숏을 `audit` 에 `guild:<기사단 id>` 키로 남긴다(`/api/admin/audit` 로 조회).

### 기기 쪽
- 시작할 때: 서버 `sharedRev` 가 이 기기 것보다 크면 서버 것을 쓴다. 같거나 서버가 비어 있으면(2단계에서 넘어옴) 이 기기 것을 올린다.
- 바뀐 게 있으면 **15초마다** 올리고, 페이지를 닫을 때(`pagehide`, keepalive)와 Electron 앱 끄기(`onFlush`) 때도 올린다. 서버가 안 닿으면 이 기기에 계속 쌓았다가 다음에 올린다.
- 409 `stale` 이면 서버 것으로 바꾸고 토스트 "다른 기기의 마을 기록으로 맞췄어요".
- **건설 시계를 서버 시각으로**: 지금은 기기 시계(`Date.now()`) 기준이라 기기 시계를 돌리면 건설이 빨라진다(1단계 메모). 바깥 페이지도 서버 응답의 `X-Server-Time` 으로 시계 차이를 맞추고, 건설 진행 = (서버 시각 − 마지막 진행 시각). 다른 기기에서 이어 받으면 `sharedAt` 부터 흐른 만큼 진행돼 있다.
- **기사 세이브에서 공용 값을 뺀다**: 지금은 getter 가 열거돼서 공용 값이 기사 세이브마다 복사돼 서버에 올라간다(2단계 메모). getter 를 열거 안 함으로 바꿔 기사 세이브엔 기사별 값만 남긴다. 운영 차감(`/api/admin/penalty` 의 gold·wood·ore)은 기사에게 걸어도 getter 를 통해 공용에서 빠진다(지금 그대로).

### 효과 규칙 (구현할 모양 — 숫자는 시작안, 아래 봇으로 확정)
- **계열**: 1차 직업의 계열(⚔️ 검사 · 🔱 창기사 · 🏹 레인저 · 🪄 마법사 · 🥊 파이터, 그 아래 2·3차 포함). 견습 기사는 계열 없음. 🗡️ 암살자는 시즌7 에 직업이 생길 때 같은 표에 한 줄 더한다 — **지금은 5계열**.
- **계열 효과**: 계열마다 그 계열에서 레벨이 가장 높은 기사 1명만 센다. 단 = ⌊그 기사 Lv ÷ 20⌋, **최대 단 = ⌈회관 Lv ÷ 2⌉**(회관 Lv10 이면 5단). 단당:
  | 계열 | 기사단 전원에게 | 단당 (시작안) |
  |---|---|---|
  | ⚔️ 검사 | 공격력 | +1% |
  | 🔱 창기사 | 최대 체력 | +1% |
  | 🏹 레인저 | 치명타 확률 | +0.5%p |
  | 🪄 마법사 | 스킬 피해 | +1% |
  | 🥊 파이터 | 공격 속도 | +0.5% |
- **다양성 효과**: Lv 50 이상 기사가 있는 계열 수 n → 공격력 +n% (모든 피해에 걸리게 공격력에 곱한다).
- **따라잡기**: 기사단 최고 레벨의 80% 아래인 기사는 경험치 ×2.
- 모두 기본 능력치라 원정·탑·미궁·성벽·레이드·결투·월드 보스에 똑같이 걸린다. 결투·레이드 전투력(서버 `profile`)에도 들어간다.
- 계산은 바깥 페이지가 한다: 기사 목록(서버 `GET /api/guilds/me` 의 직업·Lv, 슬롯 밖 기사 포함)과 회관 Lv 로 효과를 만들어 `GUILD_HOST.effects()` 로 주고, 게임 `stats()`·경험치 계산이 곱한다. 기사단 밖(플래그 끔)에선 효과 없음.
- 회관 화면: 계열 효과 표(계열 · 센 기사 · 단/최대 단 · 효과)와 다양성·따라잡기 줄.
