# 직업 캐릭터 통짜 스프라이트 전환 (초안)

- 상태: 초안. 도구 시험 전이라 구현은 아직 하지 않았고, 스펙도 확정 전이다.
- 관련 코드: `src/body2.js` (몸통 22×26), `src/limbs.js` (팔), `src/motion/*.js`·`src/cuts/*.js` (평타 컷), `src/jobs/*.js`, `src/classes.js` `CLASSES`
- 최종 갱신: 2026-10-13

## 목표

직업 캐릭터를 몸통·팔·다리·무기를 따로 조립하는 방식에서 **통짜 스프라이트 시트**(동작별 프레임)로 바꾼다.
사용자는 부위를 따로 움직이는 방식이 모션에서 어색하다고 느낀다. 몬스터보다 직업 캐릭터 퀄업이 우선이다.

## 대상

- 직업 29종: 견습 1, 1차 4, 2차 12, 3차 12 (`classes.js` `tier`)
- 직업마다 필요한 동작 후보: 대기, 걷기, 평타(무기별 연속기 1~2개), 스킬 시전, 피격, 사망, 마을 앉기
- [색깔놀이 금지](../../CLAUDE.md), 2차에서 3차로 특징 잇기 규칙은 기준 그림 단계에서 지킨다.

## 다음 단계

1. (사용자, 회사 PC) PixelLab 가입 → 무료 체험으로 견습 기사(squire) 1종 시험: 기준 그림 → 대기·걷기·평타·시전·사망
2. 마음에 들면 API 토큰을 Windows 사용자 환경변수 `PIXELLAB_API_KEY` 에 등록한다 (값은 출력·기록·커밋 금지). 한 달 정액으로 29종을 몰아서 만든다.
3. Claude: 이 스펙을 확정한다. 시트 규격(프레임 크기·화면 배율), 무기·이펙트 기준점(손·화살 발사 위치), 기존 조립 코드를 어떻게 걷어 낼지를 정한 뒤 견습 기사부터 게임에 적용하고 기존과 비교 스크린샷을 찍는다.

## 선행 과제: 바라보는 방향이 보이게 (2026-10-13 사용자 지적)

사용자는 캐릭터가 앞을 보는지 뒤를 보는지 모르겠다고 했다. 동작을 만들기 전에 이것부터 고친다.

- 원인: 투구·가면을 쓴 직업(견습 기사·검사·창기사·도끼창 계열·블레이드마스터 등 약 15종)은 눈구멍이 가운데 있고 몸이 좌우대칭이다. 얼굴이 보이는 직업(궁수·마법사 계열)은 이미 오른쪽을 향해 그려져 있어서 괜찮다.
  `look.views.side`(돌아설 때 쓰는 옆모습)도 자동 생성이라 눈구멍이 여전히 가운데다 → `dev/pixellab/lineup-before.png`.
- 규칙(안): 1) 눈구멍·얼굴판은 앞(오른쪽)으로 치우치게 하고 앞 끝에 닿게 한다. 2) 깃털·머리카락·장식은 뒤(왼쪽)로 흐르게 한다. 3) 가슴 문양·버클은 앞으로 옮긴다. 4) 뒤쪽 절반은 어두운 색이다.
- 구현(안): 해당 직업마다 `BODY2_OVERRIDE` 22×26 을 손도트로 그린다. 실루엣 차이(색깔놀이 금지)는 그대로 지킨다.
- 시안: 견습 기사만 브라우저에서 바꿔 그렸다 → `dev/pixellab/facing-mock-squire.png` (왼쪽부터 기존·시안·기존 반전·시안 반전).
- **견습 기사 적용 완료** (사용자 확인, `src/body2.js` `BODY2_OVERRIDE.squire`). 대기·전투 대기·걷기·앉기·평타 컷·돌아서기(옆·등 자동 생성)·좌우 반전이 모두 정상이다 → `dev/pixellab/squire-facing-after.png`. 실제 게임 캠프와 출정 화면에서도 확인했다.
- 남은 대상(투구·가면): 검사·성기사·블레이드마스터·창기사·용기사·도끼창·대검사·기병·폭군·천공장군·공성대장·아르콘·검성·용군주·워로드 등. 계열별로 나란히 찍어(`cutShot`) 실루엣 차이를 확인하며 진행한다.

## 선행 과제: 팔다리가 떨어져 보이는 문제 (2026-10-13 사용자 지적)

- 원인: 몸통·팔·다리·무기를 조각마다 검은 외곽선(`PAL['#']`)을 둘러 따로 그린다. 그래서 몸 안쪽 겹친 곳에도 검은 선이 남는다. 몸통과 다리 사이, 팔 테두리, 투구와 몸통 사이가 그렇다.
- 해결(적용, `src/world.js`): `drawHero` 를 래퍼로 바꾸고 기존 함수는 `drawHeroRaw` 로 이름을 바꿨다. 기사를 작은 캔버스에 그린 뒤 `softenSeams` 가 처리한다.
  외곽선 색 픽셀 중 네 방향으로 한 칸(+1px) 안에 투명이 없는 것만 고른다. 고른 픽셀은 맞닿은 색 중 어두운 쪽을 0.55배로 어둡게 칠한다.
  바깥 실루엣의 검은 선은 그대로 둔다. 한 색 잔상(tint)·무기만(onlyWeapon)·피격 번쩍임(flash)은 원래대로 그린다.
- 비용: 기사 1명당 약 +0.7ms (배율 2배 기준). 필드는 1명, 레이드는 최대 4명이다.
- 결과: `dev/pixellab/seam-before-after.png` (줄마다 왼쪽이 전, 오른쪽이 후). 전 직업에 적용된다.
- 다리 굵기(적용): 다리가 골반보다 가늘어 막대처럼 보였다.
  - 뼈대 다리(`world.js` `drawLeg`, 대기·걷기): 굵기를 [1.7, 1.45, 1.2] → [2.2, 1.95, 1.7]칸으로, 부츠 폭을 4.2 → 4.8칸으로 늘렸다. 정강이 끝은 부츠 안으로 1.2칸 올려서 걷다 두 다리가 겹칠 때 아래가 뾰족해지지 않게 했다.
  - 컷 다리(`limbs.js` `thickenLegs`, 전투 대기·평타, 손도트 약 35장): 불러올 때 다리마다 안쪽으로 한 칸 덧칠한다. 뒷다리(p/q)는 오른쪽, 앞다리(m/l/n)는 왼쪽이고, 두 다리 사이 틈은 한 칸 이상 남긴다. 그림 데이터는 그대로다.
  - 결과: `dev/pixellab/legs-poses-after.png`, `dev/pixellab/legs-walk-after.png`.

## 진행 기록

- 2026-10-13: 도구 조사, PixelLab 1순위로 결정. 사용자가 다음 날 회사에서 PixelLab을 시험하기로 했다.
- 2026-10-13: PixelLab 가입(무료 체험, 40회). MCP는 `claude mcp add pixellab ...`로 **local 범위**에 등록했다. 토큰은 `~/.claude.json`에만 있다.
  이미 열려 있던 세션에서는 MCP 도구가 안 붙는다. 그래서 `dev/pixellab/mcp.py`(토큰은 `~/.claude.json`에서 읽는다)로 HTTP JSON-RPC를 직접 호출했다.
  무료 단계는 동시 작업이 1개뿐이다. 견습 기사를 시험했고(5회 사용, 35회 남음) 결과는 `dev/pixellab/`에 있다.
  - `create_character` standard(1회, 92px 캔버스): 깔끔하지만 등신대 비율이라 게임과 안 맞는다.
  - `create_character` v3(2회, 64px): **꼬마 비율에 고퀄 도트라 기준 그림으로 적합하다.** view는 low top-down이지만 east 방향은 옆모습으로 쓸 수 있다.
  - 걷기 `walking-8-frames` 템플릿(1회): 몸이 가늘어지고 일부 프레임에서 검이 사라진다. 그대로는 쓸 수 없다.
  - 평타 v3 글 동작(1회, 84px, 9프레임): 생김새는 잘 유지되지만 베기 동작이 약하다. 후반에 몸이 정면 쪽으로 돌아간다.
  - **사용자 피드백: 새로 그린 v3는 "너무 고퀄, 얼굴 없던 기사가 갑자기 귀여운 전사가 됐다"며 결이 안 맞는다고 했다.** 그래서 방향을 바꿨다. 기존 게임 그림을 그대로 넣어 동작만 만드는 방식이다.
  - 기존 그림 추출: 브라우저에서 `drawHero(g,'squire',48,90,{mode:'fight'})`를 2배 캔버스에 그린다. 3px 블록 최빈색으로 도트 1칸=1px(30×35)로 복원해 64px에 배치했다 → `dev/pixellab/squire-orig-ref64.png`.
  - `animate_image`(첫 프레임 = 기존 그림, 8프레임, 1회씩, `dev/pixellab/anim.py`): **그림체·색은 그대로 유지된다.**
    걷기는 다리가 거의 안 움직이고 검이 내려가서 원래 자세로 돌아오지 않는다(약함).
    평타(머리 위로 들어 내려베기)는 들어 올리는 동작이 좋고 마지막에 대기 자세로 돌아온다. 하지만 검이 64px 캔버스 위로 잘리고, 정작 내려베는 프레임이 없어 팔이 뒤로 빠진다.
