# 복구 코드 재발급 (운영)

- 상태: 완료
- 관련 코드: server/index.js (`POST /api/admin/token`, `missingTokenError`), server/store.js (`reissueToken`, `isRevoked`, 컬럼 `old_token_hash`)
- 최종 갱신: 2026-10-13

## 목표
복구 코드(토큰)는 서버에 SHA-256 해시로만 있어서, 기사를 키우던 기기를 잃으면 그 기사를 다시 가져올 방법이 없었다. 관리자가 닉네임으로 새 복구 코드를 발급해 줄 수 있게 한다.

## 규칙
- `POST /api/admin/token`, 헤더 `X-Admin-Key: <ADMIN_KEY>`, 본문 `{"confirm":"TOKEN","nickname":"닉네임","reason"?:"..."}`.
  - 관리자 키가 틀리면 404 (다른 관리자 API 와 같음), 확인 문구가 없으면 400, 사람 기사가 없으면 404.
  - 닉네임은 대소문자 무시. 새 토큰은 계정 만들 때와 같은 방식(24바이트 base64url, 32자).
  - 응답 `{ ok, nickname, token }`. 토큰 원문은 이 응답에만 있다.
- 발급하면 지금 토큰 해시를 `old_token_hash` 로 밀어 두고 새 해시로 바꾼다. 인증 캐시를 비워 옛 코드는 바로 막힌다. 세이브·기록은 그대로다.
- 옛 코드로 요청하면 401 + 코드 `revoked`. 클라이언트는 `gone` 일 때만 이 기기의 기사를 모두 지우므로(`src/net.js`), 옛 기기에 있던 다른 기사들은 안전하다. 옛 기기는 "이 기기의 기록으로 계속" 토스트를 띄운다.
- 밀려난 코드는 한 단계만 기억한다 (두 번 재발급하면 첫 코드는 `gone` 이 된다 — 그 기기는 그 기사 + 같은 기기의 다른 기사 목록이 지워질 수 있다).
- 운영 기록(`audit`)에 kind `token` 으로 남는다.
