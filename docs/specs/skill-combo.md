## 목표
- 원정 중 화면 구석에서 기사가 싸우는 걸 볼 때 **"이어졌다!"** 하는 순간이 보인다 (작은 글자 + 국소 효과).
- 캠프에서 **장착 순서를 바꾸는 것**이 의미 있는 선택이 된다: 어떤 스킬 뒤에 어떤 스킬이 오느냐에 따라 합동기가 달라진다.
- 정답 강요 금지: 아무 순서로 둬도 연계는 꽤 일어난다(스킬 피해 +10% 안팎). 순서를 잘 맞추면 조금 더 (+15~20%). 못 맞춘다고 막히는 벽은 없다.
- 4단계 진화의 조건("두 스킬 ★★★ + 둘을 연계로 이은 횟수 N")에 쓸 기록을 남긴다.

## 규칙

### 1. 연계 판정
- **장착 순서 = 시전 순서** (지금 `S.t7.eq` 순서). 순서는 돌고 돈다: 마지막 칸 다음은 첫 칸.
- **연계** = 앞 스킬의 시전이 끝나고(시전 모션 끝, `k.dur`) **2초 안에** 장착 순서상 **바로 다음 칸** 스킬이 시전을 시작하면.
  - 궁극기는 순서 밖이다: 준비되면 지금처럼 맨 먼저 나가고, 궁극기 앞·뒤는 어느 칸과도 연계가 된다 (궁극기 → X, X → 궁극기).
  - 순서를 건너뛰어 나간 스킬(다음 칸이 아직 멀어서 다른 준비된 스킬이 나간 경우)은 연계가 아니다. 그 스킬이 끝난 뒤부터는 다시 그 스킬의 다음 칸을 기다린다.
  - 연계는 사슬로 이어진다 (A → B → C 면 B·C 둘 다 연계). 사슬 길이는 글자에만 쓰고 보너스는 겹치지 않는다.
  - 교전이 끊기면(적이 없어 걷는 동안) 2초가 지나 자연히 끊긴다. 돌진기로 달려가는 동안도 2초를 센다.
- **연계 효과**: 뒤 스킬 이번 시전 피해 **+20%**. 꼬리표 짝이 합동기면 아래 표대로 바뀐다.
- 왜 "바로 다음 칸만" 인가 (시뮬레이션, 아래 표): 아무 스킬이나 2초 안이면 연계로 치면 4칸에서 연계율 80% 로 순서가 거의 상관없다(순서 차이 최대 7%p). 다음 칸만 치면 연계율 60% 대, 순서 차이 최대 11~15%p 로 순서를 고르는 맛이 생긴다.

### 2. 자동 전투 — 기다렸다 잇기
스킬 하나가 끝나고 다음 시전을 고를 때 (src/world.js `fightTick` → src/skills.js `tryCastSkill`):
1. 궁극기가 준비됐으면 궁극기 (지금 그대로).
2. 다음 칸이 준비됐으면 다음 칸.
3. 다음 칸이 **1초 안에** 준비되고, 그때도 2초 연계 창 안이면 → **기다린다** (다른 스킬을 쓰지 않는다. 평타·이동은 그대로).
4. 아니면 지금처럼 준비된 스킬 중 앞 칸부터 (순서를 건너뛴다 → 연계 아님).
- 돌진기(`dashSkill`)는 사거리 밖 적에게 달려가는 규칙 그대로. 단 3번 "기다림" 중에는 다음 칸이 돌진기일 때만 돌진을 시작한다.
- 파이터 계열(기 게이지, src/jobs/fighter.js)은 "쿨이 1초 안에 끝남" 대신 "**지금 기 충전 속도로 1초 안에** 소모량을 채움" (`qiLack` ÷ 초당 기). 순서는 `qiOrder` 의 투지 기술 우선을 지킨 뒤 같은 규칙.

### 4. 합동기 (꼬리표 짝 6가지)
연계가 성립했을 때 (앞 꼬리표 → 뒤 꼬리표) 가 아래와 같으면 이름이 붙고 효과가 바뀐다. 나머지 짝은 평범한 연계 (+20%).

| 짝 | 이름 | 효과 (시안) | 보스 1마리 기대 배율 | 잡몹 무리에서 |
|---|---|---|---|---|
| ⚔️ 돌진 → 🎯 단일 | **추격** | 대상 바로 앞으로 순간이동해 시전, **확정 치명** (연계 +20% 대신) | ×1.4 안팎 (치명 확률에 따라) | 같음 |
| 🌀 광역 → 🌀 광역 | **연쇄** | 연계 +20% · 범위 +30% | ×1.2 | 더 많이 맞힘 |
| ➶ 투사체 → ➶ 투사체 | **집중** | 모든 발이 앞 스킬이 맞힌 적을 노린다 · 연계 +20% 에 피해 +20% 더 (×1.44) | ×1.4 | 한 적에 몰림 |
| 🔥 장판 → ⚔️ 돌진 | **폭발 돌파** | 돌진이 남은 장판을 지나며 터뜨린다: 앞 장판 스킬 한 번 피해의 30% 를 돌진 경로의 적에게 한 번에 · 연계 +20% | ×1.35 | 길 위의 적 전부 |
| ✨ 강화 → 아무거나 | **충전** | 뒤 스킬 피해 +40% (연계 +20% 대신) | ×1.4 | 같음 |
| 🎯 단일 → 🌀 광역 | **파편** | 연계 +20% · 앞 스킬에 맞은 적이 터져 둘레 60px 에 그 타격 피해의 50% | ×1.2 | 큰 이득 |

- 합동기 효과는 이번 한 번의 시전에만. 확정 치명은 파천(치명 0 대가) 같은 룬 규칙이 있으면 일반타 (+20% 로 돌아간다).
- 추격의 순간이동은 원정 화면 위치만 옮긴다 (몸이 대상 앞 `reachTo` 거리로). 결투·레이드는 거리가 없어 효과는 치명만.

### 5. 연출 (연출 등급표 안에서 — skill-redesign.md)
| 장치 | 뒤 스킬이 1차·2차·새 스킬 | 뒤 스킬이 3차급·궁극기 연계 |
|---|---|---|
| 글자 | 기사 머리 위 **작은 떠오르는 글자** 12px (지금 `addFloater` 크기): 평범 연계 `🔗 연계` · 합동기 `⚔️🎯 추격` · 사슬 3번째부터 `🔗×3` | 궁극기 앞·뒤 연계는 작은 이름 띠 (컷인 안 함, 궁극기 자체 컷인만) |
| 국소 효과 | 타격 지점 반경 안, 0.3초 안팎: 추격 = 순간이동 잔상 한 줄 · 연쇄 = 범위 고리가 한 번 더 번짐 · 집중 = 대상 위 작은 조준점 · 폭발 돌파 = 장판 자리 작은 폭발 · 충전 = 무기 끝 작은 빛 · 파편 = 맞은 적에서 파편 몇 개 | 같은 효과, 크기 ×1.3 |
| 정지·흔들림 | 더하지 않는다 (뒤 스킬 자기 값 그대로) | 더하지 않는다 |
| 화면 전체 (어두워짐·큰 글자) | 없음 | 없음 |

- 그림은 이미 있는 VFX 시트(src/vfx-tex.js 의 잔상·고리·섬광·파편 시트)를 위치·크기·색 램프로 다시 쓴다. **새 유료 생성은 이 단계에서 하지 않는다** (모자라면 ComfyUI 시안 → 생성 계획서 → 승인 뒤).
- 숫자: 연계로 늘어난 피해는 따로 띄우지 않는다 (뒤 스킬 숫자에 이미 들어간다).

### 6. 기록 — `S.combo` (4단계 진화가 읽는다)
```js
S.combo = {
  n: 0,                   // 지금까지 연계 총 횟수 (합동기 포함)
  p: { 'gale>iaido': 0 }, // 짝마다 횟수 — 키 = '앞 스킬 id>뒤 스킬 id' (방향 있음, 칸 이름 아닌 SKILLS id)
  j: { chase: 0 },        // 합동기마다 횟수 (귀환 보고·도감용)
};
```
- 실제 전투 시전(원정 화면·미궁·탑·성벽 = 숙련 경험치가 오르는 그 길, `tryCastSkill`)에서 연계 1번마다 +1. 미리보기·결투·레이드 재생은 세지 않는다 (숙련과 같다).
- 오프라인 원정(`simulate`): 싸운 시간 fight 초 × 지금 장착의 **짝별 분당 연계 수**(아래 근사의 시뮬 결과) ÷ 60 을 더한다 (소수 그대로 쌓는다, 보고에는 반올림).
- 원정 기록: `skmTripStart` 처럼 떠날 때 `t.combo0 = { ...S.combo.p }`, 돌아오면 귀환 보고에 "🔗 연계 132번 · 가장 많이: 질풍난무 → 일섬 48".
- 줄기를 바꾸면(전직 재선택) 기록은 남겨 둔다 (id 가 달라 섞이지 않는다).
- 진화 조건의 N 은 진화 스펙에서. 참고(시뮬): 4칸 장착에서 한 짝은 싸우는 1분에 2~5번. 숙련 ★★★(2차 11,000번 시전) 과 비슷한 무게로 두려면 N ≈ 2,000~3,000. 200 이면 몇 시간이면 찬다.

### 7. 오프라인 · 결투 · 레이드 근사
연계는 시전 타이밍이 만드는 규칙이라 시간을 돌리지 않는 계산(오프라인 `dpsOf`, 서버 결투 `server/duel.js`·레이드 `server/raid.js`)에는 그대로 못 넣는다. **평균 배율**로 녹인다:
- `comboEv(id)`: 지금 장착(순서 포함)·쿨(숙련·룬 반영 `skillCd`)·시전 시간으로 `simCombo`(이 스펙의 시뮬레이터를 src/ 로 옮긴 것, 보스 1마리·600초) 를 한 번 돌려 **스킬마다 평균 피해 배율**과 짝별 분당 연계 수를 얻는다. 장착·순서·숙련 Lv·룬이 바뀔 때만 다시 (캐시 키 = 장착 순서 + 쿨들).
- `dpsOf`: 스킬 피해 항 `extra` 에 `× comboEv(id)` 를 곱한다. 기다림 때문에 늦어지는 시간은 시뮬이 이미 반영한다.
- `profile()`: 스킬 `mult` 에 `× comboEv(id)` 를 곱해 넘긴다 → **서버 코드는 바꾸지 않는다** (재설치·서버 배포 없이). 결투·레이드 재생 연출에는 연계 글자가 안 나온다 (서버 이벤트에 없음).
- 결투 밸런스: 연계는 줄기마다 +10~20% 로 고르지 않다 → 구현 뒤 `node dev/duel-league.js --fit` 로 `T7_DUEL_LINE` 를 다시 맞춘다.
- 진행 봇(`dev/progress-bot.js`): 전후 비교로 스테이지 진행 속도 변화를 본다 (전체 DPS 약 +5~10% 예상 — 스킬이 DPS 의 절반 안팎).

## 시뮬레이션 (시안 규칙, `node dev/review/skill-combo-run.js`)
가정: 보스 1마리와 계속 교전 · 숙련 Lv20 쿨(×0.848) · 한 번 시전 피해 ∝ 쿨 · 평타는 스킬을 막지 않음 · 파이터 계열도 쿨로 근사. "피해" = 스킬 피해 합 증가율, 범위 = 장착 순서 모든 경우 중 최저~최고.

규칙 변형 (15줄기 평균):
| 규칙 | 2칸 | 3칸 | 4칸+궁 | 순서 차이 최대 | 4칸 연계율 |
|---|---|---|---|---|---|
| 아무 스킬이나 2초 안 | +8~10% | +12~15% | +16~19% | 7~9%p | 80% |
| **다음 칸만 2초 + 1초 기다림 (채택 시안)** | +8~10% | +7~13% | +10~17% | 11~13%p | 63% |
| 다음 칸만 2초, 기다림 없음 | +8~10% | +6~12% | +10~16% | 11~15%p | 58% |
| 다음 칸만 1초 + 1초 기다림 | +6~7% | +5~11% | +9~16% | 11~15%p | 56% |

- 2칸은 순서가 A → B → A 로 돌아 **순서 차이가 없다** (어느 쪽이 먼저든 같다). 퍼즐은 3칸(Lv80)부터.
- 기다림 1초의 몫은 작다 (+1%p 안팎) — 대신 "기다렸다 잇는" 모습이 화면에 보이는 게 주된 이유.

| 뇌제 | +9% | +7~12% | +9~16% | +11~15% | 뇌운 폭풍 → 섬뢰 → 뇌전 화살 → 낙뢰 |

## UI
