## 목표

사람이 손으로 고치지 않고(사용자 방침, 2026-10-16) 아트 품질을 올리려면 **생성 → 검수 → 수리**를 에이전트가 반복해야 한다. 그 첫 부품이 검수다.
지금은 "좋은지 나쁜지"를 사용자가 눈으로 보고 판정하고, 그 판정을 Claude 가 그때그때 추측한다.
검수 에이전트는 그림 한 장(또는 후보 N장)을 받아 **게임에 들어간 모습으로** 보고 합격·수리·다시 뽑기를 판정한다. 판정마다 근거(지표·결함 위치)와 고칠 방법을 낸다.
사용자는 판정이 맞았는지만 확인한다. 사용자 판정은 쌓여서 다음 검수의 기준이 된다.

## 규칙

### 전체 흐름 (4단)

| 단 | 하는 일 | 누가 | 비용 |
|---|---|---|---|
| 0. 게임 모습 만들기 | 게임 코드로 들어간 모습을 만든다. VFX 는 `src/vfx-tex.js` 로더(외곽선 벗기기·5단 양자화)와 직업색/원래 색으로 칠하기를 **실제 코드 그대로** 돌린다(`render.js`, node vm). 그다음 실제 배율(nearest)로 키우고, 어두운 필드·밝은 바탕에 합성하고, 견습 기사 옆에 두고, 흑백본을 만든다 | 스크립트 | 0 |
| 1. 규격 검사 (통과/불통) | 시트 크기 = 칸 × 프레임 수, 반투명 픽셀(알파 1~254) 없음, 프레임 칸 가장자리에 닿아 잘림 없음, 빈 프레임 없음, 루프 타일은 좌우 끝 열 이음. 칸 가장자리 닿음·반투명은 주의로만 적는다. 로더가 깎아 내는 비율은 확정 시트에도 0.6 을 넘는 것(두꺼운 외곽선을 일부러 벗기는 시트)이 8장 있어 규격이 아니라 지표 경보로 둔다 | 스크립트 | 0 |
| 2. 자동 지표 (경보·근거) | 아래 지표를 재서 기준 밖이면 경보를 띄운다. **지표만으로 탈락시키지 않는다** (보정 결과 참조) | 스크립트 | 0 |
| 3. 비평 | 검수 시트 한 장을 보고 채점표대로 점수·결함·판정·고칠 방법을 낸다 | Claude 서브에이전트 `pixel-critic` (이미지 보는 모델) | 0 (구독 안) |

- 판정 합치기: 규격 불통이면 바로 `fix`(무료 후처리로 고칠 수 있음) 또는 `regen`(다시 뽑기)이다. 그 밖에는 비평 판정을 따른다.
  지표 경보가 떴는데 비평이 `pass` 를 주면, 그 경보를 짚어 한 번 더 묻는다(근거 대조 1회).
- 후보 N장을 비교할 때는 절대 기준값 대신 **순위**를 쓴다. 지표는 같은 묶음 안에서 비교해야 더 믿을 만하다(다시 뽑기 6쌍은 대부분 지표에서 새것이 옛것보다 나았다).
- 판정 값: `pass` 합격 · `fix` 무료로 고칠 수 있음(어떤 스크립트·workbench 조작인지 적는다) · `regen` 다시 뽑기(프롬프트·기준 그림을 어떻게 바꿀지 적는다).

### 자동 지표 (게임 모습 기준)

| 지표 | 뜻 | 잡는 문제 | 경보 기준 (1차, VFX) |
|---|---|---|---|
| `crumbs` | 프레임당 4픽셀 이하 부스러기 덩어리 수 | 색종이·지저분한 파편 | > 5.2 (확정 시트 95백분위) |
| `strip` | 로더가 벗겨 낸 비율 | 검은 몸·두꺼운 외곽선이라 벗기면 테두리만 남음 | > 0.6 |
| `lrange` | 밝기 5~95백분위 폭 | 명암 없이 한 덩어리로 뭉개짐 | < 0.25 |
| `colors` | 색 수 (원래 색 시트) | AI 흐림 계조·잡색 | > 24 |
| `low` | 가장 어두운 단 비중 | 어두운 몸이 뭉개짐 | 참고 (보정 중) |
| `edge`·`lone` | 이웃과 색이 크게 다른 쌍 비율, 외톨이 픽셀 비율 | 지글거리는 노이즈 | 참고 |
| `flick`·`churn` | 이웃 프레임끼리 모양(IoU)·색이 바뀐 정도 | 깜빡임·튐 | 참고 (루프 시트에서 따로) |

기준값은 확정된 시트 분포의 5/95 백분위에서 잡는다. 사용자 판정이 쌓이면 다시 잡는다(종류별: VFX 직업색 / VFX 원래 색 / 캐릭터 / 아이콘 / 배경).

### 비평 채점표 (항목마다 1~5)

점수 눈금 (2026-10-16 보정): 5 흠 없음 · 4 작은 흠, 손 안 대도 좋음 = 게임에 들어간 괜찮은 그림의 보통 점수 · 3 눈에 띄는 흠이 있지만 게임 배율·재생 속도에서 안 거슬림 = 그대로 넣어도 됨 · 2 게임 배율에서도 거슬림 · 1 못 씀. 게임 모습(1배·장면 줄) 기준으로 채점하고, 확대해야만 보이는 흠은 한 단계까지만 깎는다.

1. **의도 일치**: 스펙의 "목표 모습" 문장대로인가. 엉뚱한 물체(칼·산·요새)가 없는가.
2. **읽힘**: 게임 배율에서 모양이 한눈에 들어오는가 (견습 기사 옆 크기).
3. **깔끔함**: 부스러기·색종이·지글거림이 없는가.
4. **명암**: 밝은 쪽이 주인공이고, 어두운 덩어리로 뭉개지지 않는가. 흑백으로 봐도 모양이 서는가.
5. **도트다움**: AI 흐림 계조, 계단 잡음, 섞인 도트 크기, 1도트 하이라이트 소실이 없는가.
6. **움직임** (프레임 2장 이상): 커짐 → 절정 → 흩어짐 흐름이 있고 튀지 않는가. 마지막 프레임이 자연스럽게 사라지는가.
7. **프로젝트 규칙**: 검은 외곽선 파티클 금지(2026-10-15), 색깔놀이 금지(캐릭터), UI 톤(남보라+은회색, 금테·튀는 색 금지).

- 합격선 (A, 2026-10-16 사용자 확정 "A 유지 + 지침 보정"): 모든 항목 3 이상이고 평균 3.5 이상. 1·3·4 중 하나라도 2 이하면 `regen` 쪽으로 기운다. (B "의도·깔끔함·명암 3+ · 평균 3.0+" 는 기각)
- 비평 입력: 검수 시트 PNG 한 장(1배 · 4배 · 게임 장면 합성 · 흑백 · 프레임 나열) + 목표 모습 문장 + 지표·경보 + **취향 기록에서 비슷한 판정 예시 3~5개**(그림과 사용자 이유).
- 비평 출력(JSON): `{ scores: {intent, read, clean, value, pixel, motion, rules}, defects: [{frame, where, what}], verdict, fix: {how, tool} }`.
- 비평은 정답(옛것/새것, 사용자 판정)을 모르는 상태로 본다. 예시는 다른 그림에서만 고른다.

### 취향 기록 (`dev/pixel-qa/labels.jsonl`)

- 한 줄 = 사용자 판정 하나: `{ file, kind, verdict: pass|fail, reason, date, source }`.
- 처음 채울 것 (이미 확정된 판정):
  - 다시 뽑기 탈락 6장 `dev/vfx5/old/*` + 이유 (k22 색종이 부스러기, e18 지글거리는 노이즈, e14 뭉개진 흙 띠, k36 검은 몸이라 벗기면 테두리만, k32 어두운 몸이 뭉개짐, k37 요새가 조각조각) ↔ 합격 6장 `src/vfx/*`.
  - 전수조사 확정 시트 170장 = 합격 (10-16).
  - 큰 창 테두리 시안 A "노이즈 같다" 탈락, 나무 톤 UI "기존이 더 깔끔하다" 탈락 (10-13).
- 같은 id 의 줄이 여럿이면 **나중 줄이 앞 줄을 덮는다** (예: k37 새 그림 — 10-16 합격 → 같은 날 블라인드 비평 지적 "아래 파편 잡부스러기, 바닥에 안 붙음"에 사용자 동의 → fail '손볼 후보').
- 사용자가 판정할 때마다 한 줄씩 더한다. 비평 예시와 지표 기준값은 이 기록에서 나온다.

### 호출 방식

```bash
python3 dev/pixel-qa/qa.py <시트.png> --kind vfx --id k22 --intent "흰·노랑 짧은 별 섬광 + 은회색 쇳조각 2~3개" [--vs 비교.png ...]
```
→ `dev/pixel-qa/out/<id>/` 에 검수 시트 PNG, `metrics.json` 이 생긴다. 그다음 세션이 `pixel-critic` 서브에이전트(Agent 도구)에 넘긴다 → `verdict.json` 이 나오고 보고 페이지가 갱신된다.
생성·수리 에이전트(다음 단계 스펙)는 이 판정을 받아 반복하고, 유료 호출 상한은 각 작업 계획서를 따른다.
