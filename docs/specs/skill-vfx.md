## 목표

전 직업의 스킬과 평타 이펙트를 하나도 빼지 않고 살펴본다. 약한 것부터 PixelLab 기반 도트 VFX로 퀄업한다.
기준은 [art-upgrade.md](art-upgrade.md)의 "AI 티 안 나는, 저해상도지만 고퀄 도트"다.
스킬 하나만 봐도 직업이 떠오르게 한다. 같은 계열 2차 직업끼리도 이펙트 색만 다른 "색깔놀이"는 금지다. 모양·궤적·타격감이 달라야 한다.

## 조사 방법

1. `dev/skills.html` 에서 스킬마다 시전 → 시작·타격·끝 세 장면을 캡처했다 (`dev/vfx-survey/<id>-{a,b,c}.png`). 캡처 방법은 아래 "캡처 재현" 참고.
   - 스킬은 **★★★ (Lv30)** 기준이다. 비교용으로 **Lv1** 타격 장면도 찍었다 (`<id>-l1.png`).
   - a = 첫 타격 전 준비 동작, b = 가장 화려한 순간(흰 섬광으로 덮이지 않은 프레임 중 화면 변화가 가장 큰 것), c = 마지막 타격 뒤 여운. 피해 숫자는 지우고 찍었다.
   - 평타는 `dev/vfx-survey/basic-<직업 id>-{a,b,c}.png` (휘두르기 시작·명중·명중 직후, 1번 동작).
   - 계열 비교: `dev/vfx-survey/family-{sword,spear,bow,mage}.png` 와 흑백판 `-gray.png` (줄 = 2차 3종 + 3차 3종, 칸 = 스킬 2개 + 평타).
2. 아래 표에 지금 연출을 한 줄로 적고, 점수와 판정을 매겼다.
   - 점수: 1 = 밋밋하다·정체성이 어긋난다 / 2 = 괜찮다 / 3 = 이미 좋다.
   - 판정: **교체**(그 스킬의 주된 그림을 고유 PixelLab 시트로 새로 만듦) / **보강**(동작·타이밍은 두고, 검흔·궤적·파편·섬광 부품을 공용 PixelLab 시트로 바꿔 끼움) / **유지**(구성·타이밍이 이미 좋음).
   - [CLAUDE.md](../../CLAUDE.md) "VFX 는 PixelLab 텍스처로 그린다"(2026-10-13): 판정과 상관없이 퀄업한 뒤의 그림은 텍스처다. 코드는 위치·크기·회전·타이밍·색 램프만 맡고, `fillRect` 사각 파티클이나 canvas path·gradient 를 주된 그림으로 새로 만들지 않는다. "유지"도 안의 사각 파티클·gradient 부품은 해당 공용 시트가 생기면 그 계열 패치 때 같이 바꿔 끼운다.
   - 메모: 문제점. 코드 위치는 메모 안에 적었다.
3. 점수가 낮은 것부터, 계열 단위로 묶어 패치한다 (아래 "퀄업 순서", 로드맵 ⑤).
4. 권투가 7종의 스킬은 처음부터 새 기준으로 만든다. 그래서 이 표에는 넣지 않고 [boxer-class.md](boxer-class.md) 에서 따로 다룬다.

전체에 걸친 문제 (계열 무관):

1. **도트가 아니라 벡터처럼 보인다.** 자국·고리·돔·광선 대부분이 안티앨리어싱된 canvas path + gradient + shadowBlur 다. 몸 그림은 3px 격자(`PX = 3`)인데 이펙트 선은 1~2px 라 결이 다르다. 대천사(`archangelFx`)는 `blur()` 필터를 쓴다. 반대로 3px 셀로 그린 것(화염 회오리·운석 바위·성채 벽돌·용 머리 스프라이트)은 이미 좋아 보인다.
2. **평타에는 타격감이 전혀 없다.** 명중 스파크·검흔·히트스톱·흔들림이 0 이다 (`hitMonster` 는 흰 번쩍임·넉백·숫자뿐). 근접 잔상도 타격 한 컷(약 45ms)에만 나온다. 원거리는 화살 2px, 착탄 효과 0.
3. **2차→3차 평타가 색만 다르다.** 12쌍 모두 모션 배열을 공유한다(`motion/legacy.js:239-245`). 흑백으로 보면 성기사↔성좌기사, 화염↔대마도사, 빙결↔빙결의 군주, 랜서↔천마장군, 석궁사수↔공성포수가 구분되지 않는다.
4. **화면 전체 번쩍임 규칙 위반.** `skills.js:22-24` 는 "궁극기 말고는 화면 전체를 번쩍이거나 어둡게 하지 않는다"(게임이 바탕화면 하단바라서)인데, 2차 스킬 11곳이 `dimBand` 로 하단바 전체를 덮는다:
   gale ★★★(`skills.js:1532`), iaido ★★★(`:1588`), headshot ★★★(`:2161`), starfall ★★★(`nightSkyFx :2349`), wideCleave ★★★(`greatswordsman.js:136,144`), ramCharge ★★★(`:229,238`), cavalryCharge ★★★(`cavalier.js:221`), blastBolt ★★★(`arbalest.js:196`), boltStorm ★★★(`:274`), chainLightning ★★★(`chainLightning.js:129,137`), thunderstorm ★★★(`thunderstorm.js:115,127`).
   캡처에서도 대검 횡참·기병 돌격·폭열탄 b 장면이 통째로 하얗게 날아간다.
5. **Lv1~9 가 너무 약하다.** `MASTERY_VIS` 0.55 + 회색 45% 섞기 때문에 1·2차 스킬 대부분이 Lv1 에서 1~2px 선 하나다 (`*-l1.png`). 플레이어가 가장 오래 보는 단계다.
6. **궁극기 공통 틀이 같다.** 12종 모두 레터박스 컷인 → 하늘 어둡게 → 첫 타 크게 → 잔타 → 막타 흰 섬광이다. 막타 섬광이 0.2~0.3초 화면을 하얗게 덮어 정작 마지막 그림이 안 보이는 것이 6종(용황·천마군단·뇌제·대마도사·파천참·성좌 강림).

## 공통 개선 후보

### 1. 공용 PixelLab VFX 시트 (계열 무관 부품)

직업의 "얼굴"이 되는 모티프(대천사·용·천마·번개 손 등)는 직업마다 따로 만든다. 그 밑에 깔리는 타격·파편 부품은 공용 시트로 묶어 여러 스킬이 같이 쓴다.
검흔·궤적·충격파·폭발·불꽃·연기·파편·섬광·마법진은 모두 이 시트에서 나온다 (CLAUDE.md 텍스처 지침).
공용 시트는 **명암 4~5단 무채색 램프**로 만들고, 불러올 때 직업 팔레트로 바꿔 칠한다(시트 하나 = 여러 직업). 단, 같은 계열 2차끼리는 서로 다른 시트를 쓰게 배정해 색깔놀이를 피한다.

| 시트 | 프레임 (안) | 쓰는 곳 |
|---|---|---|
| 베기 타격 (slash hit) | 32×32 도트 × 6 | 근접 평타 명중 전부, 강철 베기·질풍난무·횡참 자국 대체 |
| 찌르기 관통 (pierce hit) | 32×16 × 6 | 창 계열 평타, 관통 찌르기, 기병 돌격, 철갑 관통탄 |
| 박힘 착탄 (arrow hit) | 16×16 × 5 | 활·석궁 평타, 연사, 별빛 화살비, 다연장 |
| 폭발 소·대 (explosion) | 32×32 × 8, 64×64 × 10 | 폭열탄, 다연장, 대공성포, 메테오 착탄 보조 |
| 불꽃 루프 (flame) | 16×32 × 6 | 용의 숨결 ★·★★, 화염 평타 착탄, 불웅덩이 |
| 얼음 결정 생성·파쇄 (ice) | 32×32 × 8 | 얼음창, 블리자드, 빙결 평타 착탄 |
| 번개 타격 (lightning hit) | 32×48 × 6 | 낙뢰, 연쇄 번개, 뇌전 평타 착탄 |
| 성광 폭발 (holy burst) | 32×32 × 8 | 심판의 일격, 성역, 성기사 평타 |
| 마력 폭발 (arcane burst) | 32×32 × 8 | 마력 폭발 노바, 유도 마탄, 마궁수 평타 |
| 흙·바위 파편 (debris) | 16×16 × 6 | 균열·착지·분화구 공통 (`debris`·`craterFx` 대체) |
| 연기 (smoke puff) | 16×16 × 6 | 폭발 뒤, 돌진 흙먼지, 총구 연기 |
| 근접 궤적 (smear) 6종 | 48×48 × 4~6 | 평타·스킬 휘두르기 잔상: 장검·대검·쌍검·창·할버드·지팡이 (`drawCutSmear`·`slabSmear`·`drawPoleSmear` 대체). 3차는 같은 시트에 문양 프레임 추가 |
| 충격파 고리 (shockwave) | 64×16 × 6 | 착지·내려찍기·폭발 바닥 고리 (`ringFx` 대체) |
| 마법진 (magic circle) | 48×16 × 6 | 바닥 마법진·시전 원 (`circleFx`·`lightCircleFx` 대체) |

- **해상도 규칙**: 시트는 도트 단위(1도트 = 화면 3px, `PX = 3`)로 만들고 그릴 때 정수배 nearest 로 키운다. 32×32 도트 = 화면 96px. 이펙트 선의 최소 굵기는 1도트(3px)다. 1~2px 벡터 선은 쓰지 않는다.
- **외곽선**: 몸 그림과 같은 어두운 외곽(`#0b0d14`)을 바깥 테두리에만 두른다. 안쪽은 램프 명암.
- **합성**: 지금처럼 lighter 합성을 쓰되, 도트 시트 자체에 빛 단계를 그려 넣고 shadowBlur 는 쓰지 않는다.
- **시험 먼저**: 장비 아이콘 때 PixelLab 32×32 를 사용자가 "지금 16×16 감성이 낫다"며 쓰지 않았다([gear-icons.md](gear-icons.md)). 그래서 **베기 타격 시트 1장 + 폭발 1장을 먼저 시험**하고, 게임 안 전후 비교로 사용자 확인을 받은 뒤 나머지를 만든다. 감성이 안 맞으면 해상도를 16 도트로 내리거나 손도트 보정을 더한다.

### 2. 타격 정지(히트스톱)·흔들림 기준

`impact({stop, shake})` 는 `stop × fxVis × 1.3` 초 멈추고 `min(6, 3 + shake × 8)` px 흔든다. 지금은 잔타가 0.012~0.035 로 거의 느껴지지 않고, 평타는 0 이다.

**주의 — 지금의 히트스톱은 게임 시간 전체를 멈춘다.** `world.js:1173` `update()` 는 `hitstop > 0` 이면 바로 return 한다. 그래서 전투뿐 아니라 `advanceBuild`(건설)·사냥 진행·탑 광폭화 타이머까지 멈춘다.
평타 명중마다 0.025 × 1.3 ≈ 0.033초를 이 방식으로 멈추면, 공속 2/초 직업은 게임 진행이 약 6.5% 느려진다. 방치형이라 받아들일 수 없다. 그래서 정지를 두 종류로 나눈다.

- **연출 정지 (새로 만듦)**: 화면 그림만 멈춘다. 게임 시간(`update` 의 전투·건설·타이머)은 그대로 흐른다. 구현안은 둘 중 하나다 (⑤-0 착수 때 정한다).
  - (가) 기사·맞은 대상의 그리기용 동작 진행(`swing`·`anim`·스프라이트 프레임)과 이펙트 진행만 정지 시간 동안 고정한다. 피해·이동 계산은 그대로 둔다.
  - (나) 지금처럼 `update` 를 건너뛰되, 멈춘 시간만큼 다음 프레임들 `dt` 에 나눠 보충해 총 게임 시간을 맞춘다.
- **게임 정지 (지금의 `hitstop`)**: 스킬 막타와 궁극기에만 쓴다. 쿨타임이 길어 진행 손실이 무시할 만하다.

아래를 기준으로 맞춘다 (★★ 기준값, 단계별로 `MASTERY_VIS` 가 곱해진다).

| 구분 | 정지 종류 | stop | shake | 흰 섬광 |
|---|---|---|---|---|
| 평타 근접 명중 | 연출 정지 | 0.025 (치명 0.05) | 0 (치명 0.08) | 없음 |
| 평타 원거리 착탄 | 연출 정지 | 0 (치명 0.03) | 0 | 없음 |
| 스킬 잔타 (`autoHitFx` 포함) | 연출 정지 | 0.03~0.04 | 0.06~0.1 | 없음 |
| 1차 스킬 막타 | 게임 정지 | 0.06~0.1 | 0.15~0.3 | 없음 |
| 2차 스킬 막타 | 게임 정지 | 0.1~0.16 | 0.3~0.45 | 타격 지점 반경 안만 (하단바 전체 금지) |
| 2차 ★★★ 막타 | 게임 정지 | 0.16~0.22 | 0.45~0.6 | 같음 |
| 궁극기 첫 타 | 게임 정지 | 0.14~0.2 | 0.6~0.75 | 하단바 전체 가능, α ≤ 0.6 |
| 궁극기 막타 | 게임 정지 | 0.26~0.32 | 0.85~0.95 | α ≤ 0.6, 0.15초 이하 (마지막 그림이 보이게) |

- 궁극기 막타 흔들림이 낮은 신궁(0.7)·차원궁사(0.75)는 0.85 로 올린다.
- 2차 스킬의 하단바 전체 `dimBand` 11곳(위 "전체에 걸친 문제" 4번)은 타격 지점 둘레 국소 섬광으로 바꾼다 — 0.21 에서 먼저 한다 ([vfx-rule-fixes.md](vfx-rule-fixes.md)).
- 평타 연출 정지는 공속이 빠른 직업에서 끊겨 보일 수 있다. 공속 2/초 이상이면 절반으로 줄인다.
- 진행 손실 확인: 퀄업 전후로 10분 자동 사냥 골드가 ±1% 이내여야 한다 (아래 수용 기준).

### 3. 숙련 단계(`MASTERY_VIS`) 유지 여부

- **유지한다.** Lv1 → ★★★ 로 모양이 바뀌는 것은 숙련의 보상이다.
- 다만 바닥을 올린다: `MASTERY_VIS` [0.55, 0.8, 1, 1.2] → **[0.7, 0.85, 1, 1.2]**, Lv1 회색 섞기 45% → **25%**. Lv1 에서도 스킬 고유 모양(초승달·십자·마름모 등)이 3px 굵기로 보여야 한다.
- 주의: `fxVis` 는 히트스톱에도 곱해진다. 바닥을 올리면 Lv1 정지 시간이 0.55 → 0.7 배로 약 27% 늘어난다. 게임 정지는 막타·궁극기에만 남기므로 영향은 작지만, 위 진행 손실 확인에 Lv1 상태도 넣는다.
- 퀄업한 시트도 단계별로 크기·프레임 수만 바꾸고, 시트 자체는 같은 것을 쓴다.

### 4. 버그 → 0.21 자잘이로 옮김 ([vfx-rule-fixes.md](vfx-rule-fixes.md))

- 공허궁 평타 꼬리 색이 청록으로 나온다: `WEAPONS.voidBow.arrow` 에 `rgb` 없음 → `world.js:2729` 기본값.
- 3차 burst 색 상속으로 잔상과 섬광 색이 어긋남: 월광쌍검(빨강), 용황창(보라), 태양궁(흰색).
- 결투·레이드에서 원거리 평타가 12×2 막대로만 그려진다.

- 검사 계열은 지금도 가장 완성도가 높아(유지 3종) 마지막이다.
- 패치마다 계열 비교 그림(`family-*.png`)을 다시 찍어 전후를 남긴다.
