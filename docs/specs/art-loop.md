## 목표

사용자는 손으로 그림을 고치지 않는다(2026-10-16 방침). 그래서 그림 한 장의 일감을 받으면 에이전트가 **뽑고 → 검수하고 → 고치고 → 다시 검수**하는 일을 스스로 돌려야 한다. 합격한 결과만 사용자 앞에 놓는다.
사용자가 하는 일은 두 번뿐이다: **① 묶음 계획 승인**(무엇을, 어떤 길로, 유료 몇 회까지) **② 최종 전후 비교 확인**. 그 사이에는 묻지 않는다.

## 규칙

### 역할

| 역할 | 누가 | 하는 일 |
|---|---|---|
| 계획 | 세션 (시범은 세션이 `jobs.json` 을 썼다. `art-planner` 지침은 다음 묶음에서) | 일감 표(아래)를 보고 길(무료 먼저)·후보 수·유료 상한·프롬프트·기준 그림을 정해 `plan.json` 을 쓴다. 묶음 전체를 검토 페이지 한 장으로 사용자 승인에 올린다 |
| 생성 | 스크립트 + Claude 에이전트 | 길에 따라 후보를 만든다. 무료: ComfyUI 시안(Windows), PixelLab `vfx_workbench`·`pixelart_workbench`(구독 무료), 기존 그림을 프레임·코드로 변형. 유료: PixelLab 키 그림·애니(최종으로 고른 것만) |
| 검수 | `qa.py` + `pixel-critic` | 후보가 여럿이면 `rank.py` 방식으로 비평 1회 순위 → 1등을 한 장 검수. 판정 `pass` / `fix` / `regen` (합격선 A: 전 항목 3+ · 평균 3.5+) |
| 수리 | Claude 에이전트 `art-repairer` + `repair.py` | 비평의 결함·고칠 방법을 읽고 **수리 연산 목록**(JSON)을 쓴다. `repair.py` 가 그대로 실행한다. 에이전트는 픽셀을 직접 찍지 않고 연산만 고른다. 시험 폴더에서 `repair.py`·`qa.py` 로 안을 몇 개 돌려 보고 고른다(비평은 부르지 않음). **수리는 이번 줄기에서 점수가 가장 높은 판에 한다** — 나빠진 수리 위에 덧대지 않는다 |
| 진행 | `loop.py` | 일감마다 상태를 파일로 들고, 다음에 할 일을 정한다. 세션이 `loop.py next`(전체) 또는 `loop.py task <묶음> <일감>`(한 일감의 지시문)을 부르고, 에이전트에게 "이 명령을 실행해 나온 지시를 따르라"고 넘긴다. 중간에 끊겨도 다시 부르면 이어 간다 |

### 흐름 (일감 하나)

```
계획 승인 ─▶ 생성(후보 N) ─▶ 순위 ─▶ 검수 ─┬─ pass ─▶ 완료(전후 비교 대기)
                    ▲                       ├─ fix ──▶ 수리 ─▶ 검수 (최대 3번)
                    └──── regen (최대 2번) ──┘
```

- `fix` 인데 수리 3번으로도 `pass` 가 안 나오면 `regen` 으로 넘긴다.
- `regen` 은 비평의 "다시 뽑을 때 바꿀 것"을 계획 에이전트가 프롬프트·기준 그림에 반영해 다시 생성한다. 무료 길을 먼저 다시 쓴다.
- **정체**: 줄기(원래 그림 또는 마지막 다시 뽑기 이후) 안에서 두 판 연속 평균 점수가 오르지 않으면 수리를 그만두고 **다시 뽑기로 넘어간다**(2026-10-21 사용자 결정 — 예전엔 여기서 멈춰서 k37 이 유료 한도·다시 뽑기를 남긴 채 끝났다). 다시 뽑기는 무료 길 먼저, 유료는 남은 한도 안에서.
- **멈춤**: regen 2번을 다 썼거나(정체로 넘어온 것 포함), 유료 상한에 닿고 무료 길도 다 썼으면 멈춘다. 이때는 지금까지 **가장 점수 높은 판**(원래 그림 포함)을 남기고 이유를 적는다. 원래 그림보다 못하면 원래 그림을 그대로 둔다.
- 원래 그림도 같은 검수를 받아 기준점이 된다(전후 점수 비교).
- 결과 판 고르기: 합격 판 > 평균 높은 판 > 2점 이하 항목이 적은 판 > 나중 판. 원래 그림보다 평균이 낮으면 원래 그림.
- 생성은 그림 본체를 PixelLab(·ComfyUI)으로만 만든다. 코드로 도형·파티클을 찍어 만든 판은 규칙 위반으로 버린다(CLAUDE.md "VFX는 PixelLab 텍스처로").
- 바닥 기준 이펙트(`texFx` anchor 'b')는 일감에 `"anchor": "b"` 를 적는다 → 검수 시트에 땅선을 긋고 장면에서 칸 바닥을 기사 발에 맞춘다(안 하면 비평이 "떠 있다"고 잘못 본다).

### 수리 연산 (`repair.py`, 무료·결정적)

| 연산 | 하는 일 | 쓰는 경우 (비평 결함) |
|---|---|---|
| `drop_crumbs n` | n 픽셀 이하 떨어진 덩어리 지우기 (프레임마다) | 부스러기·잔점·색종이 |
| `deink to` | 거의 검은 무채색(로더가 외곽선으로 보는 색)을 색 있는 어두운 색으로 | 로더가 안쪽 검정을 둘레 평균으로 메워 생기는 흐린 계조·색 폭증 (e30: 442색 → 9색) |
| `fill_holes n` | 그림 안에 갇힌 작은 투명 구멍을 둘레 색으로 메우기 | 눈 같은 구멍 |
| `drop_isolated` | 이웃 없는 1픽셀 점 지우기 | 외톨이 점 |
| `lift_dark t` | 밝기 t 미만을 t 로 끌어올리기 (색상 유지) | 어두운 덩어리로 뭉개짐 |
| `quantize n` | n 색으로 줄이기 (중앙값 분할, 투명 유지) | 색 과다·AI 흐림 계조 |
| `recolor a→b` | 특정 색 무리를 다른 색으로 | 탁한 회색 얼룩 |
| `frames order [...]` · `drop i` · `dup i` | 프레임 순서·빼기·복제 | 흐름 뒤섞임·급변 |
| `fade_out k` | 마지막 프레임을 테두리부터 깎은 프레임 k 장 덧붙이기 (`burst.py` 식 침식) | 툭 끊김·사라짐 없음 |
| `fade_in k` | 첫 프레임을 줄이거나 아래부터 드러낸 프레임 k 장 앞에 | 나타남 없음 |
| `anchor bottom` · `center` | 프레임마다 바닥/가운데 맞춤 | 바닥 기준인데 떠 있음 |
| `fit w h` | 규격 칸에 맞춰 자르기·여백·nearest 정수배 | 크기·칸 잘림 |
| `tile_seam` | 루프 타일 좌우 끝 열 맞추기 | 이음매 |
| `workbench changes cleanup` | PixelLab `pixelart_workbench`(구독 무료·결정적)의 `edit --changes`(brush·patch_pixels·flood_fill·map_colors·copy_region·outline) 와 `repair --ops`. 시트를 n×1 로 잘라 올리고 결과 격자를 받아 다시 잇는다. 프레임 번호는 0부터(넘길 때 1을 더함). 호출은 `dev/pixellab/mcpw.py` (맥은 Claude Code MCP 설정의 키를 읽는다, 출력 안 함) | 별 찍기·먼지 덩어리·끊긴 띠 잇기처럼 새 픽셀을 그려야 하는 손질 |

- `workbench` 의 `patch_pixels` 는 연산 전체 48픽셀까지(`PATCH_MAX`). pilot2 첫 e30 수리안이 스크립트로 계산한 2,453픽셀을 찍어 넣었다 → 코드로 그리기를 우회하는 것이라 막았다. 넓은 손질은 붓 획·`flood_fill`·구역(`select_mask` 다각형) + `map_colors`·`copy_region` 으로, 수리 담당이 눈으로 보고 고른다.
- 프레임 수가 바뀌면 시트 등록(`frames:`)도 바뀐다 → 결과에 적고, 게임 적용 때 같이 고친다.
- 연산은 원본을 덮어쓰지 않고 새 판(`v2`, `v3` …)을 만든다.

### 돈 (CLAUDE.md "유료 생성 서비스는 아껴 쓴다")

- 유료 호출은 **승인된 계획 안에서만** 한다. 계획에는 일감마다 "무엇을·왜 유료여야 하는지·호출 상한·실패 시 수리법"을 적는다.
- 자기 몫은 응답 usage 합계로 센다(`log.jsonl` 에 호출마다 한 줄). 계정 잔량은 안전 바닥 300 으로만 본다. 바닥 아래면 유료 단계는 건너뛴다.
- 비평·계획·수리 에이전트 호출은 Claude 구독 안이라 돈으로 세지 않지만, 일감당 비평 호출 수를 기록한다.

### 결과와 적용

- 결과: `dev/art-loop/<묶음>/<일감>/` — `plan.json`, `v1…vN.png`, 판마다 검수 결과, `log.jsonl`(단계·판정·점수·호출), `final.png`.
- 보고: `report.py` 가 `dev/review/art-loop-<묶음>.html` 을 만든다. 일감마다 전후(게임 모습 1배·4배·기사 옆), 점수 변화, 밟은 단계, 쓴 호출을 한 줄 카드로 보여 준다.
- **게임 적용은 사용자 확인 뒤에** 한다: 확인된 일감만 `src/vfx/<id>.png` 로 옮기고 시트 등록·`GAME_VERSION` 을 고쳐 배포 규칙대로 푸시한다.
- 사용자의 최종 판정(좋아짐/아님 + 이유)은 `dev/pixel-qa/labels.jsonl` 에 쌓인다 → 다음 비평의 예시가 된다.
