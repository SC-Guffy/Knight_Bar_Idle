# 도전의 탑 몬스터 무리

- 상태: 초안 (사용자 확인 대기)
- 관련 코드: src/data.js (`TOWER_*`), src/tower.js (`towerMonster`·`towerBossFloor`·`towerKillReward`·`clearTowerFloor`·`sweepTower`), src/world.js (`updateTower` 의 `enter`·`fight`, `fightTick`, `drawTowerBody`), src/ui.js (`viewTower` 안내 문구, 서브 콘텐츠 목록 설명), dev/tower-pack-sim.js (밸런스 시뮬레이터), dev/review/tower-packs.html (검토 페이지)
- 최종 갱신: 2026-10-13

## 목표

사용자 원안: "도탑 몬스터 무리지어서도 나오게끔 설정" ([roadmap.md](roadmap.md) 시즌6 자잘한 것, 진행 순서 ① 0.21 자잘이).

지금 탑은 모든 층이 "정예 1마리와 1:1"이라 층마다 손맛이 같다. 일부 층에 정예 무리를 섞어서 오르는 리듬을 바꾼다.

- 무리 층에서는 광역 직업(할버디어·화염술사·뇌전술사 계열)이 시원하게 쓸어 담는 맛을 느낀다.
- 단일 대상 직업(저격수·석궁사수 계열)도 무리 층이 넘기 힘든 벽이 되면 안 된다. **최고 층(벽)은 무리 때문에 거의 움직이지 않아야 한다.**
- 보상·소탕·층 곡선·랭킹은 그대로 둔다. 바뀌는 것은 "그 층에서 무엇과 싸우는가"뿐이다.

## 규칙

### 어느 층이 무리인가
- **층 번호의 끝자리가 3·6·9인 층**이 무리 층이다 (3F·6F·9F·13F·16F·19F·23F …). 10층마다 3개 층, 전체의 30%.
- 확률로 정하지 않고 층 번호로 고정한다. 같은 층은 언제 와도 같은 상대라서 "몇 층에서 막혔다"가 운에 따라 바뀌지 않는다. 다시 도전할 때 운으로 넘는 일도 없다.
- 보스 층(끝자리 0)은 지금처럼 보스 1마리다. 체크포인트(끝자리 1)로 시작하는 첫 층은 항상 정예 1마리다.

### 무리 구성
- 무리는 **3마리** (`TOWER_PACK_N = 3`). 몬스터 종류는 그 스테이지 몬스터 풀(`monsterPool(towerStage(f))`)에서 마리마다 따로 뽑는다 (섞여 나온다).
- 마리당 세기는 **같은 층 정예 1마리를 기준으로** 정한다.

  | | 체력 | 공격력 | 골드·경험치 |
  |---|---|---|---|
  | 정예 1마리 (지금) | 스테이지 몬스터 ×2 (`TOWER_ELITE_HP`) | ×2.2 (`TOWER_ELITE_ATK`) | ×3 |
  | 무리 1마리 | 정예 ×**0.4** = 스테이지 몬스터 ×0.8 (`TOWER_PACK_HP = 0.4`) | 정예 ×**1.0** = ×2.2 (`TOWER_PACK_ATK = 1`) | 정예 ÷3 = ×1 |
  | 무리 합계 | 정예 ×1.2 | (한 번에 1마리만 때린다, 아래) | 정예와 같음 (×3) |

- 체력 합계를 정예의 1.2배로 둔 이유:
  - 몬스터는 기사 앞에 16px 간격으로 줄을 선다(`fightTick` 의 `prev + 16`). 몬스터 공격 사거리는 `MELEE_REACH 14 + 몸 반폭`이라 **맨 앞 1마리만 기사를 때린다.** 그래서 받는 피해는 정예 1마리와 비슷하다.
  - 앞 몬스터가 쓰러지고 다음 몬스터가 다가오는 동안은 싸우는 중이 아니다. 이때는 광폭화 시계(`tw.ft`)도 멈추고, 휘두르던 공격도 끊긴다. 체력을 정확히 3등분(합 1.0배)하면 단일 대상 직업까지 무리 층이 더 쉬워진다. 시뮬레이션에서 성기사 +2.9칸, 화염술사 +6.8칸이었다.
  - 1.2배일 때 단일 대상 직업은 정예 층과 거의 같고(−1.0~+1.3칸), 광역 직업만 눈에 띄게 유리하다(+2~+6.5칸). 아래 "밸런스 근거" 표를 본다.
- 등장 자리: 정예가 나오던 `TW_SPAWN_X`(114)를 가운데로 14px 간격 → x = 100·114·128 (탑 폭 150, 사다리 134 안쪽). 등장한 뒤에는 원정과 같은 줄서기 규칙으로 다가온다.

### 광폭화
- **그대로 둔다**: 한 층에서 `TOWER_ENRAGE_SEC` 10초 넘게 싸우면 `TOWER_ENRAGE_DOUBLE` 2.5초마다 공격력이 2배가 된다.
- 무리 층에서는 **살아 있는 모든 마리**에 같은 배율이 붙는다. 지금 `fight` 코드가 이미 `monsters` 전체에 적용하고 있다.
- 시계는 지금처럼 기사가 교전 중(`knight.fighting`)일 때만 흐른다. 마리 사이에 다음 몬스터를 기다리는 시간은 세지 않는다.
- 무리 층만 광폭화를 2초 늦추는 안(12초)도 재 봤다. 결과는 잡음 범위 안이었다(성기사 +0.8 → +1.6칸, 저격수 −1.0 → −1.4칸, 석궁사수 −0.7 → −0.3칸). 그래서 규칙을 하나 더 만들지 않는다.

### 층 돌파·보상 (바뀌지 않음)
- 층은 **무리 3마리를 모두 잡아야** 돌파한다 (`fight` 의 `monsters.some((m) => !m.dying)` 그대로).
- 📖 비전서: 깬 층마다 1권, 10층 단위 첫 돌파 묶음(`towerFirstTomes`). **무리 층도 똑같이 1권**이다.
- 처치 골드·경험치: 마리당 정예의 1/3이라 층 합계는 정예 층과 같다. 처치 수(`run.kills`)는 마리 수대로 센다. 무리 층은 3이다.
- **🧹 소탕은 바뀌지 않는다**: 입장권 1장으로 최고 층 수만큼 📖 (`sweepTower`). 소탕은 전투를 하지 않으므로 무리와 상관없다.
- 층 난이도 곡선(`TOWER_STAGE0`·`TOWER_STAGE_PER`·`TOWER_CURVE`)·입장권·체크포인트·랭킹(🗼 최고 층)은 그대로다. 기록을 옮길(migrate) 필요가 없다.

### 구현 메모
- `src/data.js`: `TOWER_PACK_FLOORS = [3, 6, 9]` (층 % 10), `TOWER_PACK_N = 3`, `TOWER_PACK_HP = 0.4`, `TOWER_PACK_ATK = 1`.
- `src/tower.js`: `function towerPack(floor)` → 무리 층이면 `TOWER_PACK_N`, 아니면 1. `function` 선언으로 둔다. dev 시뮬레이터가 `window.towerPack = () => 1` 로 덮어써서 "정예만" 기준선을 잴 수 있어야 한다.
  `towerMonsters(floor)` → 몬스터 배열을 돌려준다. 정예·보스 층은 지금 `towerMonster` 와 같은 1마리다. 무리 층은 위 표대로 마리마다 종류를 따로 뽑는다. `towerMonster(floor)` 는 탑 탭 "첫 상대" 카드용으로 남긴다.
- `src/world.js` `updateTower` `enter`: `monsters = towerMonsters(floor).map((m, j, a) => makeMonster(m.type, m.boss, toWorld(TW_SPAWN_X + (j - (a.length - 1) / 2) * 14), { ...m, atk0: m.atk, rage: 1 }))`.
- `towerKillReward` 는 마리마다 불리므로 고칠 것이 없다.

## UI

- **탑 층 번호** (`drawTowerBody`): 무리 층은 `13F ×3` 처럼 뒤에 `×3` 을 붙이고 주황(`#ffb070`)으로 쓴다. 우선순위는 최고 기록 층 금색 > 보스 👑 빨강 > 무리 주황 > 보통 흰색. 다가오는 층이 무리인지 미리 보인다. 새 이모지는 쓰지 않는다(`👥` 는 도트 아이콘이 없다).
- **등장 알림**: 무리가 나타날 때 무리 위에 `⚔ 무리 ×3` 플로터(`addFloater`, 주황, 12px)를 띄운다. 보스처럼 큰 배너(`showBanner`)는 쓰지 않는다. 30% 층마다 배너가 뜨면 시끄럽다.
- **탑 탭 안내 문구** (`viewTower` 의 `.hint`): "층마다 정예 몬스터 하나, 10층마다 보스." → "층마다 정예 몬스터 하나 — **3·6·9로 끝나는 층은 정예 무리 3마리** — 10층마다 보스."
- **서브 콘텐츠 목록 설명** (ui.js `desc: '층마다 정예 하나, 10층마다 보스 — …'`): "층마다 정예, 3·6·9층은 무리, 10층마다 보스 — 오를수록 📖 비전서".
- "첫 상대" 카드는 체크포인트(끝자리 1) 층이라 늘 정예 1마리다. 바꾸지 않는다.
- 정산 화면·지난 도전 카드는 그대로다. 처치 수만 무리만큼 늘어난다.

## 밸런스 근거 (2026-10-13 시뮬레이션)

도구: [dev/tower-pack-sim.js](../../dev/tower-pack-sim.js). `dev/skills.html` 에서 게임의 `update()` 를 1/60초씩 돌려 실제 탑 전투를 잰다. 평타·스킬(숙련 ★★)·광폭화·층 사이 체력 이월이 모두 들어간다.
직업마다 몬스터에 배율을 걸어 "정예만 나올 때의 벽"을 맞춘 뒤, 무리 설정에서 최고 층이 얼마나 움직이는지 본다. 사용법은 [dev-testing.md](../dev-testing.md) "도전의 탑 무리 시뮬레이터"에 있다.

**① 잘게 쪼갠 곡선** (`curve: 'fine'`, 보스 없음, 칸마다 체력 ×1.08·공격력 ×1.06 ≈ 세기 7%, 실제 1층 ≈ 5칸, 모든 층이 무리). 정예만 대비 최고 칸 변화:

| 직업 (2차, 12회) | 공격 범위 | 체력 1/3 (합 1.0) | **체력 0.4 (합 1.2)** | 0.4 + 광폭화 12초 | 1/3 + 공격 ×1.3 |
|---|---|---|---|---|---|
| 성기사 | 단일 | +2.9 | +0.8 | +1.6 | −0.7 |
| 검성 | 단일 | +1.2 | +0.4 | +0.4 | +0.5 |
| 저격수 | 단일 | −1.0 | **−1.0** | −1.4 | −1.2 |
| 빙결술사 | 단일 | +1.9 | +0.4 | +0.5 | +0.3 |
| 석궁사수 | 단일 | +0.0 | −0.7 | −0.3 | −1.8 |
| 마궁수 | 3발 나눔 | +0.1 | −0.6 | −0.8 | −1.0 |
| 대검전사 | 3마리 | +1.7 | +0.5 | −0.4 | +0.3 |
| 용기병 | 2마리 | +2.7 | +1.9 | | +1.5 |
| 랜서 | 2마리 | +4.6 | +2.9 | | +3.8 |
| 할버디어 | 9마리 | +3.9 | +1.0 | | +2.7 |
| 화염술사 | 폭발 | +6.8 | +4.1 | | +4.3 |
| 뇌전술사 | 연쇄 | +6.4 | **+4.5** | | +4.8 |

3차(체력 0.4, 8회): 신궁 −0.9 · 빙결의 군주 +0.5 · 검신 +0.6 · 차원궁사 +0.8 · 천마장군 +1.0 · 성좌기사 +1.1 · 공성포수 +1.3 · 용황 +2.1 · 전쟁군주 +2.6 · 파천검왕 +3.0 · 뇌제 +6.1 · 대마도사 **+6.5**.

- 체력 0.4 에서 단일 대상 저격 계열이 가장 손해다(−1칸 ≈ 세기 −7% ≈ 실제 −0.2층). 광역 마법 계열이 가장 이득이다(+6.5칸 ≈ 실제 +1.2층).
- 무리 층이 광역에게 1층쯤 쉬워져도 바로 다음 정예 층이 벽이라 최고 층은 거의 오르지 않는다(②).

**② 실제 층 곡선** (`curve: 'real'`, 10층마다 보스, **끝자리 3·6·9층만 무리**, 체력 0.4). 정예만 벽 ≈ 15층, 8회씩:

- 2·3차 24종 모두 최고 층 변화가 **−0.5 ~ +0.8층**이고 평균은 **−0.04층**이다. 정예만일 때도 회차마다 ±0.5층은 흔들린다.
- 최고 층 분포: 정예만 {13: 5, 14: 87, 15: 95, 16: 5} → 무리 {13: 5, 14: 100, 15: 78, 16: 8, 17: 1}.

## 수용 기준

검토 페이지 `dev/review/tower-packs.html` (로컬 서버에서 연다): 층별 구성 표(마리당 체력·마리 수를 바꿔 볼 수 있다), 직업별 유불리·최고 층 변화·처치 시간 막대, 시뮬레이터 다시 재기, 구현 뒤 실제 게임에서 13층을 여는 콘솔 스니펫.


- [ ] 무리 층 판정: 콘솔에서 `[1,2,3,6,9,10,13,20,29,30].map(towerPack)` → `[1,1,3,3,3,1,3,1,3,1]`.
- [ ] 마리당 수치: `towerMonsters(13)` 은 3마리다. 각 마리의 체력 = `monsterStats(towerStage(13), false).hp × 2 × 0.4`, 공격력 = `× 2.2`, 골드·경험치 = 스테이지 몬스터 ×1 이다. `towerMonsters(14)`·`towerMonsters(20)` 은 지금 `towerMonster` 와 같은 1마리다 (콘솔 스니펫으로 비교).
- [ ] 등장: 웹 게임을 오프라인으로 띄우고(`docs/dev-testing.md`) `S.tower.best = 12` 로 13층부터 시작하면, 몬스터 3마리가 x 100·114·128 쯤에 나타나 탑 폭 안에서 모두 보인다. `⚔ 무리 ×3` 플로터가 뜨고 층 번호가 `13F ×3` 주황이다 (스크린샷).
- [ ] 줄서기: 근접 기사 앞에 무리가 16px 간격으로 서고, 맨 앞 1마리만 공격 모션을 낸다 (스크린샷 또는 `monsters.map(m => !!m.anim)`).
- [ ] 광폭화: 무리 층에서 10초 넘게 싸우면 살아 있는 모든 마리의 `m.rage` 가 같이 오르고, `😡 광폭화!` 배너가 한 번 뜬다. 마리 사이 빈 시간에는 `tw.ft` 가 늘지 않는다.
- [ ] 돌파: 3마리를 다 잡아야 `13F 돌파!` 가 뜬다. 📖 는 1권 오르고, `S.tower.run.kills` 는 3 오른다. 2마리만 잡았을 때는 돌파하지 않는다.
- [ ] 소탕 불변: `S.tower.best = 25` 에서 `sweepTower()` 의 반환값과 `S.tomes` 증가가 25다 (구현 전과 같다).
- [ ] 보상 불변: 같은 층을 정예만(`window.towerPack = () => 1`)으로 깼을 때와 무리로 깼을 때 층 합계 골드·경험치가 같다 (`S.tower.run.gold`·`exp` 비교, 골드·경험치 배율 1로).
- [ ] 밸런스: `towerSim.compare([...towerSim.TIER2, ...towerSim.TIER3], { pack: {} }, { curve: 'real', seeds: 8 })` 를 구현 뒤 다시 돌린다. 이때 무리는 게임이 직접 내고, 기준선은 `window.towerPack = () => 1` 로 잰다. 모든 직업의 최고 층 변화가 **±1층 안**이고 평균 변화는 **±0.3층 안**이다.
- [ ] 안내 문구: 탑 탭 `.hint` 와 서브 콘텐츠 목록 설명에 "3·6·9층은 무리"가 보인다.
