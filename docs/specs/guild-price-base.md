# 기사단 공용 골드 가격 기준 (기사단 최고 스테이지)

- 상태: 구현 (0.30.4, 사용자 확인 전) — 안 A 확정 (사용자 10-22)
- 관련 코드: src/core.js (`priceBest`·`finishLap`·`rushPrice`·`tradePrice`·`supplyPrice`), src/raid.js (`ticketPrice`), src/tower.js (`towerTicketPrice`), src/dungeon.js (`dgTicketPrice`), src/castle.js (`castleTicketPrice`), src/tree7.js (`t7SlotCost`), src/guild.js (`freshShared.best`·`bindShared` 의 `S.guildBest`), server/index.js (`sanitizeShared` 의 `best`), dev/guild-bot.js·dev/guild-server-test.mjs
- 관련 스펙: [guild.md](guild.md) (공용 범위 안 A — 골드·목재·철광석·마을 공용), [build-rush.md](build-rush.md), [currency-roles.md](currency-roles.md)
- 최종 갱신: 2026-10-22

## 문제

2026-10-22 사용자 보고: 건물 즉시 완료(시간 스킵)·소모품 값이 **보고 있는 기사**에 따라 달라서, 저렙 기사로 들어가면 너무 싸게 파바박 올릴 수 있다.

원인: 골드로 사는 가격 8곳이 전부 `monsterStats(S.best).gold`(= **그 기사의** 최고 스테이지 잡몹 골드 2×1.2^(스테이지−1))에 묶여 있다. 기사단 모드에선 골드가 공용이라, 본캐가 번 골드를 부캐 화면에서 부캐 스테이지 값으로 쓸 수 있다. 1.2^스테이지라 차이가 어마어마하다 — 본캐 250 · 부캐 20 이면 같은 물건이 **약 10¹⁸ 배** 싸다(사실상 공짜).

| 가격 | 사는 것 | 공용으로 새는가 |
|---|---|---|
| 건설 즉시 완료 `rushPrice` | 공용 건설 | **샌다** — 마을 전체 |
| 창고 교역 `tradePrice` | 🪵🪨 (공용, 양은 건물 비용 기준) | **샌다** |
| 재료의 미궁 입장권 `dgTicketPrice` | 기사별 입장권 → 🪵🪨 보상(양은 건물 비용 기준 = 기사 스테이지 무관) | **샌다** — 부캐가 싸게 산 표로 공용 재료를 퍼 온다 |
| 보급품 `supplyPrice` (도시락·물약·부적·영약) | 기사별 아이템 | 그 기사에만 — 하지만 공용 골드 가치가 무너진다 |
| 레이드·탑·성벽 입장권, 7차 슬롯 `t7SlotCost` | 기사별 | 위와 같음 |

건물 업그레이드 비용 자체(`buildCost`)는 건물 Lv 만 보므로 기사와 무관하다. 다만 재료를 사 오는 교역·미궁과 시간을 사는 즉시 완료가 기사 스테이지를 따라가서 결과적으로 "건물이 싸게" 올라간다.

## 목표

- **공용 골드로 내는 값은 누가 사도 같다.** 골드의 가치는 기사단 전체가 정하므로 가격 기준도 기사단 하나로 둔다.
- 기사단을 안 쓰면(1명) 지금과 완전히 같다.

## 규칙 (안 A 확정)

1. **가격 기준 스테이지** `priceBest()` = 기사단 모드면 **기사단 최고 스테이지**(기사단에 있었던 모든 기사의 `S.best` 최댓값, 내려가지 않음), 아니면 `S.best`.
   - 공용 상태에 `best` 를 둔다. 각 기사가 `S.best` 를 갱신할 때(그리고 불러올 때) `shared.best = max(shared.best, S.best)`.
   - 내려가지 않는다: 본캐를 슬롯에서 빼거나 지워도 값이 그대로(빼 놓고 싸게 사는 길 차단).
2. 위 표의 **골드 가격 8곳 전부** `S.best` 대신 `priceBest()` 를 쓴다 (수치 배율 `BUILD_RUSH_GOLD`·`TRADE_GOLD`·`*_TICKET_GOLD`·`SUPPLIES.price` 는 그대로).
3. **얻는 쪽은 그대로 기사 스테이지**: 원정 골드, 룬 넘침 골드(`gear.js`), 미궁 💰 칸 등 보상은 계속 그 기사 `S.best`. (보상까지 올리면 부캐가 본캐만큼 번다 = 반대 방향 치팅)
4. 앞으로 공용 골드를 쓰는 새 가격은 `priceBest()` 로 만든다 (core.js `priceBest` 주석에 규칙으로 남김).
5. 구현: 공용 상태 `best` 는 기사 세이브에 안 들어가는 getter `S.guildBest` 로 연결된다. 올리는 때 = 기사가 기사단에 붙을 때(`bindShared`) · 스테이지를 넘을 때(`finishLap`) · 가격을 셀 때(`priceBest`). 서버 상한 99999.
6. 배포 순서 안전: 서버가 아직 옛것이라 `best` 를 버려도, 클라이언트는 슬롯에 붙은 기사들의 최고 스테이지로 다시 채운다(본캐가 슬롯에 없으면 그때만 낮게 잡힘).

### 부캐 쪽 영향 (확인 필요)

- 부캐의 보급품·입장권이 본캐 값이 된다. 부캐 혼자 번 골드로는 못 사지만 골드가 공용이고 본캐 수입이 받쳐 주므로 실제로 막히진 않는다(후반 골드는 잉여 — balance-diligence).
- 대안 B: 공용으로 새는 3곳(즉시 완료·교역·미궁 입장권)만 바꾸고 보급품·나머지 입장권은 기사 스테이지 그대로(부캐 따라잡기 윤활). 단, 이러면 "보는 기사마다 값이 다른" 상태가 남아 사용자 보고 2번(소모품)이 그대로다 → **안 A(8곳 전부) 추천.**

### 서버

- 공용 상태 검사(`sanitizeShared`)가 아는 키만 받으므로 `best`(1 이상 정수, 상한 99999)를 추가한다. Render 배포 필요(재설치 불필요 — main.js·preload.js 안 건드림).

## 수용 기준

- [x] 기사단: 본캐(250)·부캐(20) 두 화면에서 즉시 완료(화면 137ac 같음)·교역(부캐 2.08e22 → 본캐 ×1.3 = 오늘 2번째)·보급품(화면 4종 같음, 물약 1.04e21)·레이드 6.24e21·탑 1.56e22·미궁 3.12e22·성벽 1.56e22·스킬 슬롯 3.12e21 가 **똑같다** (바꾸기 전 부캐 값은 약 10¹⁸배 쌌다)
- [x] 본캐를 슬롯에서 빼고, 서버 공용 상태를 다시 받아 새로 고침해도 부캐 `priceBest()` = 250
- [x] 부캐 원정 골드·룬 넘침 골드는 부캐 스테이지 그대로 (보상 코드는 안 바꿈 — `gear.js`·`season.js`·`worldboss.js`·`dungeon.js dgUnitValue` 는 `S.best`)
- [x] 기사단 끔(`?guild=0`): `priceBest()` = `S.best`, 레이드 입장권·보급품 값이 옛 식과 같다 (best 1·100 으로 확인)
- [x] 서버가 공용 상태 `best` 를 저장·돌려주고 99999 로 자른다 (`dev/guild-server-test.mjs` 전부 통과 — 첫 저장 빈 마을 규칙에 맞춰 테스트도 고침)
- [x] 기사단 봇 전후 비교 (`HALL_FIRST=1 node dev/guild-bot.js --days 7 --seeds 5`, 5시드 중앙값):

  | | 1명 | 5명 · 바꾸기 전 | 5명 · 바꾼 뒤 (봇 그대로) | 5명 · 바꾼 뒤 + `TRADE_MAIN_ONLY=1` |
  |---|---|---|---|---|
  | 본캐 최고 스테이지 | 240 | 260 | 240 | **267** |
  | 본캐 전투력 (효과 켬) | 3.10e6 | 6.95e6 | 2.91e6 | 5.21e6 |

  | 건설 중 즉시 완료 가능 비율 | 88.6% | 98.0% | 79.9% | 78.8% |

  - 1명 열은 그대로다(기사단 없으면 값이 같다).
  - "봇 그대로" 열은 봇이 **모든 기사로 교역을 할 수 있는 만큼 다 한다.** 본캐가 원정을 나가 있는 동안 부캐가 오늘 교역 횟수(공용)를 본캐 값으로 다 써서 초반 골드를 말린다. 바꾸기 전엔 이 교역이 부캐 값이라 거의 공짜였다 — 바꾸기 전 기사단 이득의 일부가 이 구멍이었다.
  - 사람처럼 교역은 한 기사만 하게(`TRADE_MAIN_ONLY=1`) 하면 본캐 267 · 전투력 ×1.7 로, guild.md 4단계 확정 때(269)와 비슷하다. 건설 시간 벽(마을 Lv 합 ≤ 1명의 1.5배)도 그대로다. 남는 골드로 건설을 바로 끝낼 수 있던 시간 비율은 98% → 79% 로 줄었다(즉시 완료가 더는 거저가 아님).
