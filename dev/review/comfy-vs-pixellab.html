ComfyUI(로컬) vs PixelLab — VFX 텍스처 비교

2026-10-13 · RTX 4070 Ti SUPER 16GB · 스펙: docs/specs/art-upgrade.md "로컬 생성(ComfyUI) 시험" · 텍스처 규격: docs/specs/skill-vfx.md (1도트 = 게임 화면 1.5px)
결론W1b 초승달 검흔H1 명중 5프레임C1 초승달+속도선W1 휘두르기 궤적 속도·횟수방법
재생 속도 기사 옆에 놓기
결론: 섞어 쓰기 — PixelLab 이 주력, ComfyUI(Z-Image) 는 시안·대량 후보·단순 모양 보조
  • 품질은 PixelLab 이 확실히 위다. PixelLab 은 32px 도트를 직접 그려서 1도트 하이라이트·끝이 가늘어지는 선·의도된 명암이 살아 있다. ComfyUI 는 1024px 그림을 32칸으로 줄이는 방식이라 가장자리에 계단 잡음이 생기고, 반짝이·가는 속도선 같은 1~2도트 디테일이 뭉치거나 사라진다.
  • 모델은 Z-Image Turbo 가 SDXL 보다 낫다. 글 지시(초승달, 속도선, 별 섬광)를 훨씬 잘 따른다 (C1 쓸 만한 후보 6/8 vs 1/8). SDXL 은 도트 질감은 좋지만 회색 바탕·그림자·엉뚱한 구도(칼, 산, 링)를 자주 넣는다.
  • 여러 프레임은 "기준 그림 고정 img2img" 가 된다. 키 그림을 코드로 살짝 바꾸고(키우기·부수기·각도로 드러내기) 다시 그리게 하면 프레임끼리 모양·색이 이어진다. 다만 흩어지는 마지막 프레임은 PixelLab 처럼 정돈된 파편이 아니라 덩어리로 남는다. 한 장에 5프레임 그리기는 C1 은 일관되지만 변화가 거의 없고, W1 은 실패했다.
  • 속도는 무제한에 가깝다. 1024px 한 장 6.5~7.4초, 하루 8시간 돌리면 약 4,000장. 텍스처 1장(키 후보 4~8장 + 프레임 4장)이 약 1~1.5분이라 121장 전체 시안을 하루 안에 뽑을 수 있다.
  • 제안: ① 최종 텍스처(특히 평타 H·W, 궁극기 F)는 PixelLab 으로 뽑는다. ② 콘셉트가 안 정해진 것(1점 스킬 새 콘셉트 등)은 ComfyUI 로 수십 장 시안을 먼저 뽑아 모양을 고른 뒤, 그 그림을 PixelLab 에 기준 그림으로 넣는다 → PixelLab 횟수를 아낀다. ③ 모양이 단순하고 커서 축소에 강한 것(초승달 C1, 고리 C3, 큰 폭발 C5, 먹구름 C15)은 ComfyUI 결과를 바로 써 볼 만하다.
사용자 결정 필요: PixelLab 만 / ComfyUI 만 / 섞어 쓰기 중 무엇으로 갈지. 아래 그림을 보고 판단해 달라.

방법 (재현)

  • 설치: C:\AI\ComfyUI (OneDrive 밖), Python 3.13 가상환경 .venv, PyTorch 2.14 cu130. 모델 약 26GB 는 C:\AI\ComfyUI\models. 서버: .venv\Scripts\python.exe main.py --listen 127.0.0.1 --port 8188
  • 모델: SDXL sd_xl_base_1.0 + sdxl-vae-fp16-fix + LoRA nerijs/pixel-art-xl (dpmpp_2m karras 25스텝 cfg 6) · Z-Image Comfy-Org/z_image_turbo bf16 + qwen_3_4b_fp8_mixed + ae + LoRA tarn59/pixel_art_style_lora_z_image_turbo (res_multistep 8스텝 cfg 1, AuraFlow shift 3)
  • 스크립트 (dev/comfy/, ComfyUI 가상환경 파이썬으로 실행): comfy.py API 호출 · post.py 후처리 · trial.py 후보/애니/시트 · bench.py 속도 · look.py 밀착 시트
  • 후처리: 테두리 중앙값을 바탕색으로 보고 떼기 → 도트 칸마다 덮인 비율 40% 이상이면 칠하고 색은 칸 안 최빈 밝기 단계 → 그림 안 밝기 순위(15·20·25·20·20%)로 5단 램프(PixelLab W1b·H1·C1 에서 뽑은 흰~하늘색) → 3칸 미만 덩어리 지우기 → 바깥 외곽선 #0b0d14. 마지막 두 프레임은 흰 단을 깎아(밝기 상한 3·2) 사라지게 한다.
  • 기준 그림 고정 img2img: 키 그림 바탕을 검정으로 → 프레임마다 코드로 변형(H1: 0.7배 → 원본 → 조각 밀어내기 3단계, W1: 호 중심 기준 각도로 위에서부터 드러내기 → 꼬리 부수기) → denoise 0.45 로 다시 그림 → 모든 프레임에 같은 자르기 상자.
  • 원본 1024px 그림은 저장소 밖 C:\AI\comfy-raw. 저장소에는 도트 결과(out/cand, out/anim)와 축소 미리보기(out/thumb)만 둔다.
