한 줄 요약 — 기사단 하나에 기사 최대 10명, 슬롯 2~5칸의 기사가 전부 동시에 돌아요. 슬롯을 누르면 새로 고침 없이 그 기사 화면으로. 입장권은 기사마다 따로, 계열을 다양하게 키우면 기사단 전원이 세져요. 로그인은 Google, Electron 앱은 연결 코드.

찾은 것

  • 본캐를 크게 끌어올리는 건 기사단 효과가 아니라 공용 골드다(①). 초반엔 골드가 훈련을 막는데, 기사 4~5명이 번 골드가 한 지갑으로 모여 본캐가 일찍 훈련을 몰아 받고 그게 눈덩이가 된다. 후반엔 1명이어도 골드가 남아돈다.
  • 목재·철광석은 창고 비축(시간 기준)·교역(하루 횟수)에서 오고 그게 공용이라 기사 수만큼 늘지 않는다 → 마을 Lv 합은 1명과 같다. 건설 시간 벽은 안 무너진다. (즉시 완료할 골드는 1명이어도 87% 시간에 있다 — 기사단만의 문제가 아님)
  • 시작안 회관(Lv 3/6/10, 최대 Lv 없음)은 슬롯이 하루 만에 다 열리고 계열 효과 최대 단이 회관을 따라 끝없이 커진다 → 회관 최대 Lv 과 슬롯 Lv 을 다시 잡았다(③).
  • 따라잡기: 새 기사가 본캐 레벨의 80% 에 닿는 시간이 본캐의 0.49배(골드 공용) · 0.75배(골드 기사별) — 공용이면 목표(절반 안팎) 그대로.
  • 회관을 먼저 짓는 추천 수치(③)에선 골드 공용과 기사별의 차이가 작다(스테이지 269 대 260) — 회관이 목재·철광석을 먼저 가져가 초반 눈덩이가 줄어서.

3. 공용 범위 — 골라 주세요

안 A — 마을 공용 추천안 B — 핵심 재화 1종만 공용
공용🪙 골드 · 🪵 목재 · 🪨 철광석 · 마을 건물(+회관) · 창고 비축·교역 · 대장간 시설 · 건설 대기열 1개📖 비전서 하나 (또는 💠 강화석)
기사별💎 💠 📖 📕 🧱 🎲 📜 · 보급품 · 입장권 전부 · 장비 · 훈련 · 스킬나머지 전부 — 마을도 기사마다 따로
느낌부캐가 마을을 같이 키워서, 새 기사도 좋은 마을에서 시작 = 윤활유. 강화·스킬은 기사별이라 각자 할거리가 남음기사마다 경제가 완전히 독립. 부캐는 계열 효과로만 도움
위험골드가 기사 수만큼 → 건설 즉시 완료로 건설 시간 벽이 무너질 수 있음 → 진행 봇으로 재고 즉시 완료 값 조절새 기사가 마을 Lv1부터 → 부캐 육성이 지루함. 공유 1종 수급이 기사 수 배

안 A 근거: 창고가 마을 건물이라 "창고 공용 = 마을 하나"가 자연스럽고, 지금 병목인 🪵🪨 은 건설 시간에 막혀 있어서 수입이 늘어도 바로 터지지 않아요. 💎·💠·📖 를 기사별로 두면 강화·스킬 성장 속도는 기사마다 그대로예요.

4. 동시 진행 방법 — 1단계 기술 검증

콘텐츠지금 누가 계산?안 보는 기사 처리
레이드 · 결투 · 월드 보스 · 교관 승부서버재생 건너뛰고 바로 정산 + 칩에 결과 점. 레이드 대기방도 기사마다 따로 유지
원정 · 탑 · 미궁 · 성벽클라이언트 실시간 (world.js 전역 한 벌 + S 하나)아래 후보 중 검증
후보 ① 기사마다 숨은 iframe 추천 시작안
같은 게임을 기사 수만큼 iframe 으로 띄워 전역 상태가 저절로 나뉨 → world.js 그대로. 바깥 페이지가 매 프레임 각 기사의 update(dt) 를 부르고, 그림은 보는 기사만. 전환 = iframe 보이기(새로 고침 없음). 공용 재화는 바깥 객체 하나를 각 S 에 getter/setter 로 연결.
확인할 것: 5명 동시 프레임 30↑ · 기사당 메모리 증가량 · iframe 안에서 window.parent.bar(Electron) 사용
후보 ② world.js 를 "기사마다 월드 객체"로 리팩터링 — 정확하지만 3,000줄+ 수술. ①이 안 될 때.
후보 ③ 안 보는 기사의 탑·미궁·성벽은 근사 계산 — 직접 볼 때와 결과가 달라져서 쓰지 않음.

앱을 완전히 끄면 지금처럼 오프라인 규칙(원정만 시뮬, 탑·미궁·성벽은 그 자리 정산). 한 기사단은 한 기기에서만 — 다른 기기 로그인 시 먼저 기기가 멈춰요.

5. 기사단 효과 계산기 (시작안 — 값을 바꿔 보세요)

     

다양성: Lv ↑ 계열 개 → 모든 피해 % · 최대 단 = 회관 Lv ÷ 2 (시작안)

목표: 6계열을 다 키운 기사단 본캐가 본캐 하나만 키운 경우보다 약 +15~20%. 같은 계열 두 명은 최고 레벨 한 명만 세요 (이것저것 키우게). 콘텐츠 전용 보정은 넣지 않아요.

따라잡기: 새 기사는 기사단 최고 레벨의 80% 까지 경험치 ×2.

6. 로그인 흐름

웹

Google 버튼→ID 토큰→서버 POST /api/auth/google 검증→기사단 토큰→없으면 기사단 이름 → 첫 기사 닉네임

Electron 앱 (재설치 없음)

앱: 6자리 코드 (10분)→아무 브라우저: 게임 웹 "기기 연결"→Google 로그인 + 코드 입력→앱이 토큰 받음

Google 은 앱 안 로그인 창을 막고, 지금 preload.js 에 외부 브라우저 열기가 없어서 이 방식. 게임 모음 사이트 iframe 에서 Google 버튼이 막히면 같은 연결 코드로. 준비물: Google Cloud OAuth 클라이언트 ID (사용자 계정으로 만들어야 함 — 순서는 구현 때 안내). 클라이언트 ID 는 공개값, 비밀키 안 씀.

7. 수용 기준

  • Google 로그인 → 기사단 이름 → 첫 기사 → 시작
  • 다른 브라우저 같은 Google 계정 → 같은 기사단
  • 연결 코드로 앱(웹 두 탭으로 흉내)이 기사단 진입
  • 슬롯 클릭 → 0.2초 안에 전환, 새로 고침 없음
  • A 탑 진행 중 B 로 갔다 오면 A 탑이 실제로 진행돼 있음
  • A 레이드 대기방 준비 유지, 끝나면 A 칩에 결과 점
  • 5칸 동시 프레임 30↑, 메모리 측정 기록
  • 같은 계열 두 명은 최고 레벨 한 명만
  • 공용 재화: A 가 번 것을 B 화면에서 바로 사용
  • 진행 봇: 기사 1명 vs 5명 7일 비교
  • 두 기기 동시 접속 시 먼저 기기 멈춤
