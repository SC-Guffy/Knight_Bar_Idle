# 기사 키우기 ⚔️

화면 하단에 붙어 사는 방치형 기사 키우기 (Electron, macOS).
기사를 원정 보내 두고 다른 일을 하다가, 돌아오면 정산하고 정비해서 다시 보내는 게임입니다.

```
npm install
npm start
```

### 업데이트 배포

설치된 앱은 게임 화면(`index.html`, `src/`)을 웹 버전(GitHub Pages, https://sc-guffy.github.io/Knight_Bar_Idle/)에서 불러온다.

- **게임 코드만 바꿨으면** `main`에 푸시하면 끝. 웹 버전이 1~2분 안에 갱신되고, 켜져 있는 앱도 5분마다 확인해서 저장한 뒤 새 버전으로 다시 불러온다 (`ui.js`의 `watchForUpdates`).
- 게임 업데이트를 푸시할 때는 `src/data.js`의 `GAME_VERSION`을 올린다. 캠프 창 탭 줄 오른쪽 끝에 이 값이 나온다.
- **`main.js`·`preload.js`를 바꿨을 때만** 설치 파일을 새로 만들어 Releases 에 올린다. 웹 코드에서 새 `window.bar` 기능을 쓸 때는 예전 앱에 없을 수 있으니 `if (window.bar.새기능)`으로 확인하고 쓴다.
- 웹을 불러오지 못하면(오프라인 등) 앱에 들어 있는 파일로 연다. `npm start`(개발)는 항상 로컬 파일을 열고, `KB_WEB=주소`로 다른 웹 주소를 지정할 수 있다.
- 예전(0.1.x) 앱의 로컬 세이브는 처음 웹 주소로 열 때 한 번 옮긴다 (`main.js`의 `migrateLocalStorage`, `store.html`).

### 설치 파일 만들기

```
npm run dist:mac   # dist/KnightBar-mac-arm64.dmg, KnightBar-mac-x64.dmg
npm run dist:win   # dist/KnightBar-win-x64.exe
```

- `productName` 은 영문(`KnightBar`)으로 둔다. 한글이면 패키징된 앱이 켜자마자 죽는다. Finder 표시 이름만 `CFBundleDisplayName` 으로 "기사 키우기".
- 세이브·계정은 앱 이름과 상관없이 `~/Library/Application Support/knight-bar` 에 둔다 (`main.js` 의 `setPath`).
- Apple 서명이 없어서(ad-hoc 서명) 받은 사람은 처음 열 때 경고가 뜬다. 시스템 설정 → 개인정보 보호 및 보안 → "그래도 열기".

## 플레이 루프

```
[출정] 보급품(부적·영약) 고르기 → 출발
   ↓  하단바에서 방치 — 스태미나가 줄고 가방에 전리품(장비·골동품·소비 아이템)이 쌓임
[귀환] 스태미나 소진 / 가방 가득 / 귀환 명령 → 캠프로 걸어서 복귀, macOS 알림 + 메뉴바 ❗
   ↓  캠프의 기사(말풍선)나 HUD 클릭 → 캠프 창
[정산] 원정 일지 확인 → 전리품 챙기기 (장비는 창고로, 골동품은 재화로, 소비 아이템은 보급품으로)
   ↓
[정비] 마을 건설 · 훈련 · 장비 장착·강화 · 보급품 구매 · 휴식(스태미나 회복) → 재출정
```

- **스태미나**: 원정 중 초당 소모(기본 100 = 4분, 완전 휴식 3분). 여관을 올릴수록 원정이 길어져(Lv10 약 42분, Lv20 약 10시간) 점점 방치할 수 있습니다. 캠프에서만 회복되고 도시락으로 즉시 회복할 수 있습니다.
- **스테이지**: 화면을 왼쪽에서 오른쪽으로 한 바퀴 지나가는 게 한 스테이지입니다. 잡몹이 화면에 깔리고 보스는 항상 우하단에 서 있으며, 보스를 잡고 오른쪽 끝을 넘어가면 다음 스테이지가 됩니다.
- **필드**: 20스테이지마다 필드가 바뀝니다 — 🌿 푸른 초원(1~20) → 🪦 묘지 무덤(21~40) → 🐸 독안개 늪(41~60) → 🌋 화산 동굴(61~80) → ❄️ 얼어붙은 설원(81~100) → 🏰 마왕성(101~120) → 🌑 심연의 균열(121~140) → ☁️ 천공의 섬(141~160) → 🏜️ 모래폭풍 사막(161~180) → 🌊 심해 신전(181~200) → 🍄 요정의 숲(201~220) → ⚙️ 고대 기계 유적(221~240) → 💎 수정 동굴(241~260) → ⚡ 폭풍의 봉우리(261~280) → 🌌 별의 끝(281~, 끝없음 · 20스테이지마다 몬스터 색이 바뀜). 필드마다 나오는 몬스터·보스·지형이 다르고, 필드 마지막 스테이지의 **필드 보스**를 한 번이라도 잡아야 다음 필드가 열립니다. 필드 보스는 필드마다 넘어야 하는 벽이라 일반 보스보다 체력 ×4 · 공격력 ×1.6 (약 5스테이지 더 센 셈, 보상은 1.5배)입니다. 캠프 아래쪽에서 열린 필드를 골라 출정할 수 있습니다 (잠긴 필드는 바로 다음 하나만 보입니다).
- **쓰러짐**: 스태미나 10을 잃고 그 자리에서 다시 일어납니다. 그 원정 동안은 보스 없이 잡몹만 바퀴를 돌며 파밍하고(HUD에 🔁, 보스에게 졌으면 같은 스테이지·잡몹에게 졌으면 한 스테이지 아래), 다음 출정 때 보스에 다시 도전합니다.
- **마을**: 한 번에 한 건물만 지을 수 있고, 원정 중에도 공사는 계속됩니다.
  - 🎯 훈련장: 훈련 레벨 상한
  - 🛏️ 여관: 최대 스태미나와 휴식 속도
  - 📦 창고: 가방 칸 수
  - ⚒️ 대장간: 공격력 배율
- **훈련**: 골드로 공격력·체력·방어·수완을 올립니다. 모두 상한이 없고(훈련장 레벨 상한만 있음) 캠프에서만 할 수 있습니다.
  - 공격력·체력·방어는 단계마다 ×1.286 씩 오르는 절대값입니다.
  - 🛡️ 방어: 받는 피해 감소 = 방어/(방어 + 10×그 스테이지 몬스터 공격력) — 올릴수록 효율이 떨어지고, 스테이지 속도에 맞춰 훈련하면 20~50% (직업·장비의 피해 감소와 곱으로 합쳐 최대 85%)
  - 💰 수완: 골드·경험치 획득 Lv당 +3% (몬스터 처치·레이드 보상)
  - 공속·치명은 훈련으로 못 올리고 **직업**과 **장비**(무기 공속 · 장신구 치명)에서만 얻습니다. 예전 공속·치명 훈련 단계는 쓴 골드를 돌려줍니다.
- **장비**: 무기(공격력 + 등급별 공속, 대장간 배율 적용)·갑옷(체력)·장신구(등급별 치명 확률 + 치명 피해) 세 부위. 공속·치명은 스테이지와 상관없이 등급으로 정해지고 강화로는 단계당 4%만 오릅니다. 줍는 대로 장비 창고에 쌓이고, 🗡️ 장비 탭에서 자동 장착과 일괄 판매를 할 수 있습니다. 공격력·체력의 절대값은 훈련(단계마다 ×1.286)과 레벨이 쌓고, 무기·갑옷은 그 위에 등급별 %를 곱합니다(일반 +50% ~ 태초 +685%, 강화 배율이 곱해짐). 줍는 스테이지와 상관없이 등급이 높으면 항상 더 셉니다.
- **일괄 판매**: 팔 등급을 칩으로 체크하고 버튼 하나로 팝니다(두 번 눌러 확인). 기본은 일반~영웅만 체크되어 있습니다. 🔗 세트 장비는 별도의 세트 칩(기본 해제)을 체크했을 때만 팔리고, 장착 중인 장비는 항상 빠집니다.
- **장비 도감**: 부위·등급마다 고유한 이름·설명·도트 아이콘을 가진 장비 39종 (`src/data.js`의 `GEAR_ITEMS`·`GEAR_SPR`). 등급이 높을수록 희귀해서, 원정 1회 기준 영웅은 4~5회에 1개, 전설은 약 40회에 1개꼴입니다. 영웅·전설 장비는 줍는 순간 배너로 알리고, 가방에서는 실루엣과 `???`로만 보이다가 캠프에서 챙길 때 정체가 드러납니다.
- **강화**: 부위마다 +25까지. 강화 단계는 장비가 아니라 **부위**에 붙어 있어서 다른 장비로 바꿔 껴도 유지됩니다. 골드·철광석(+10부터 마력석)이 들고, 구간이 올라갈수록 성공률이 떨어지고 실패 시 하락(+6~)·초기화(+16~) 위험이 생깁니다. 📜 보호 주문서를 켜 두면 하락·초기화가 나왔을 때 대신 부서집니다. 확률표는 `src/data.js`의 `ENHANCE` (0에서 +20까지 평균 약 700회, +25까지 약 4.8만 회).
- **🔴 레드닷**: 글을 읽지 않아도 다음에 누를 곳이 보이도록, 지금 바로 할 수 있는 일이 있는 곳에 빨간 점이 찍힙니다. 하단바 HUD·캠프 말풍선 → 캠프 탭 → 탭 안의 버튼 순으로 따라가면 되고, 하고 나면 저절로 사라집니다 (`src/ui.js`의 `campDots`).
  - 원정 보고: 챙길 전리품·안 본 보고 / 마을: 지금 지을 수 있는 건물(건설 중이면 🔨) / 훈련: 다음 단계 비용의 2배가 모인 훈련 / 장비: 자동 장착하면 더 세지는 부위 / 전직: 전직 가능·비전서로 레벨업할 수 있는 스킬 / 레이드: 안 연 처치 상자·대기실 / 출정 버튼: 휴식이 끝났고 가방이 비었을 때
  - 원정 보고는 창을 닫을 때 지우지만, 점은 원정 보고 탭을 한 번 보면 꺼진다.
- **오프라인**: 앱을 꺼 둔 시간도 원정·휴식·건설이 그대로 진행된 것으로 계산됩니다.

## 계정 · 랭킹 · 결투

- **계정**: 첫 실행 때 닉네임을 정합니다. 닉네임이 곧 계정이고 서버에서 중복될 수 없습니다(한글·영문·숫자·_ 2~12자, 대소문자 무시).
- **저장**: 진행은 이 기기에 먼저 저장되고 30초마다(그리고 앱을 끌 때) 서버에 올라갑니다. 오프라인이어도 게임은 계속되고, 연결되면 다시 올라갑니다. 켤 때 서버 기록이 더 최근이면 그걸 불러옵니다.
- **계정 변경**: 메뉴바 아이콘 → `계정 변경…`에서 새 기사를 만들거나, 이 기기의 다른 기사로 바꾸거나, 다른 기기의 기사를 **복구 코드**로 가져옵니다. 복구 코드는 같은 창에서 볼 수 있습니다.
- **랭킹**: 캠프의 🏆 랭킹 탭. 최고 스테이지순 / 이번 결투 시즌 점수순으로 볼 수 있습니다.
- **결투**: 랭킹에서 다른 기사의 ⚔️ 결투 버튼. 두 기사가 서버에 저장된 능력치(원정 버프 제외)로 자동으로 싸우고, 서버가 계산한 결과를 캠프 창에서 재생합니다. 이기면 상대의 결투 점수(Elo)를 가져옵니다. 결투는 5초에 한 번.
  - 결투에서는 체력이 최소 4배로 늘고, 공격력이 체력을 크게 앞지르는 후반에도 서로 평타만 주고받으면 약 12초는 버티도록 두 기사의 체력 배수를 같이 키웁니다 (한 방에 끝나 사거리 긴 쪽이 무조건 이기지 않게, `server/duel.js` 의 `DUEL_SEC`).
  - 방어(받는 피해 감소)는 결투·레이드에서 내 **최고 스테이지** 몬스터 기준으로 계산합니다 (낮은 필드에 있어도 같음).
- **📢 서버 확성기**: 누군가 장비를 **+20 이상 강화에 성공**하거나 강화가 **초기화**되면 모든 기사의 하단바 위쪽으로 소식 한 줄이 흘러갑니다 (`POST/GET /api/shouts`, 서버 메모리에 2분만 보관, 클라이언트는 15초마다 확인 — `src/ui.js`의 `loadShouts`, 그리기는 `src/world.js`의 `drawShout`).
- **결투 시즌**: 3일마다 자동으로 바뀝니다 (한국 시간 2026-10-01 00:00 시즌 1 시작, `server/season.js`). 결투 점수·승패는 시즌마다 1000점 / 0승 0패에서 다시 시작합니다.
  - 시즌 순위와 보상은 그 시즌에 **직접 결투를 1번 이상 건** 기사만 대상입니다. 도전받기만 한 기사도 점수는 오르내리지만 순위에 오르지 않습니다.
  - 시즌이 끝나면 서버가 순위를 남기고(`duel_seasons`·`season_rewards` 테이블), 다음에 접속했을 때(입장 직후·10분마다·랭킹 탭) 보상을 받습니다.
  - 순위별 보상(`src/season.js`의 `SEASON_TIERS`): 재화는 내 최고 스테이지 기준, 상자는 열 수 있는 가장 높은 레이드 보스의 처치 상자(레이드를 아직 못 열면 상자 대신 재화가 늘어남).

| 순위 | 재화 배율 | 처치 상자 |
|---|---|---|
| 🥇 1위 | ×6 | 3 |
| 🥈 2위 | ×4.5 | 2 |
| 🥉 3위 | ×3.5 | 2 |
| 🏅 4~10위 | ×2.5 | 1 |
| ⭐ 상위 30% | ×1.6 | – |
| 🎖️ 참가 | ×1 | – |

## 보스 레이드

- 캠프의 🐉 레이드 탭. **1~4명**이 파티를 짜서 보스를 잡습니다. 방 목록에서 들어가거나 보스를 골라 방을 만들고, 파티원이 모두 ✅ 준비하면 방장이 출정합니다.
- 로비(방 목록·참가·준비·출정)는 서버가 들고 있고, 방에 있는 동안 2초마다 상태를 주고받습니다. 90초 동안 소식이 없으면 방에서 나간 것으로 봅니다.
- 전투는 결투처럼 서버가 파티원들의 **저장된 능력치**로 끝까지 계산하고, 모두의 캠프 앞 하단바에서 같은 전투가 재생됩니다. 보스는 주로 맨 앞 기사를 때리고, 몇 초마다 전원에게 광역기를 씁니다. 보스마다 전용 도트와 공격 연출이 있고, 광역기는 기를 모은 뒤(스킬 이름 표시) 터집니다 — 슬라임 킹 점프 충격파, 고블린 족장 도끼·회오리, 리치 킹 해골탄·해골 손, 늪의 군주 물기·독안개, 화염룡 화염구·화염 숨결, 서리 거인 얼음 바위·고드름, 마왕 암흑 구체·흑염 기둥. 75초가 지나면 광폭해지고 120초 안에 못 잡으면 실패.

## 도전의 탑

- 스테이지 30에 도달하면 캠프의 🗼 탑 탭에서 도전할 수 있습니다. 기사가 하단바를 걸어 오른쪽 끝의 탑 문으로 들어가, **화면 오른쪽 세로 띠**에서 층마다 싸우고 사다리로 오릅니다. 쓰러지거나 스태미나가 바닥나거나 ⬇️ 후퇴하면 지금 높이에서 바닥까지 떨어진 뒤 캠프로 돌아옵니다.
- 층마다 정예 몬스터 1마리(같은 스테이지 몬스터의 체력 ×2 · 공격력 ×2.2), 10층마다 보스(같은 스테이지 보스의 체력 ×2 · 공격력 ×1.6). 한 층에서 10초 넘게 싸우면 몬스터가 **광폭화**해 2.5초마다 공격력이 2배씩 오른다 — 못 넘는 층에서 늘어지지 않고 확실히 쓰러진다. 난이도는 스테이지 `25 + 층 × 3` 급 (1층 = 28, 10층 = 55, 20층 = 85, 50층 = 175스테이지) — 한 층마다 체력 ×1.86 · 공격력 ×1.6 의 가파른 계단. 시작은 체크포인트(깬 10층 단위 다음 층)부터.
- 스태미나를 원정과 같은 속도로 씁니다. 오프라인 진행은 없고, 앱을 끄거나 다시 불러오면 그 층에서 끝낸 것으로 정산합니다.
- **보상**: 처치 골드·경험치 + 📖 비전서 — 한 번의 도전에서 3층을 깰 때마다 1권(하루 3권까지), 10층 단위를 처음 넘으면 `3 + 층/10`권 (10층 4권, 20층 5권, …).
- **창 처리**: 새 앱(0.3.0~)은 탑에 들어갈 때 창을 화면 전체 높이로 키웁니다(`window.bar.setOverlay`, 클릭은 계속 통과). 창이 하단바 높이뿐이면(그 전 앱, 좁은 iframe) 같은 탑이 하단바 오른쪽 끝 150px 안에 그려집니다 — 재설치 안 한 유저도 같은 콘텐츠를 그대로 즐깁니다. 판정은 창 높이로 하므로 웹 버전(브라우저)에서도 화면 오른쪽에 세로로 그려집니다.
- **처음 하는 일 안내(FTUE)** — 탑 → 비전서 → 스킬 강화가 한 줄로 이어지게 (`src/ui.js`의 `guideTick`·`guideTab`, 본 단계는 `S.guide`): 탑이 열리는 순간 배너와 안내 → 캠프를 열면 🗼 탑 탭이 먼저 열리고 레드닷 → 첫 비전서를 얻으면 "⚜️ 전직 탭에서 강화" 안내 → 캠프를 열면 전직 탭이 먼저 열리고 숙련도 패널 맨 위에 "👉 레벨업을 눌러 보세요"와 맥동하는 버튼 (Lv1→2는 비전서 1권) → 첫 강화 때 바뀐 쿨타임·위력과 다음 목표(Lv10 ★숙련)를 알려 주고, 비전서가 없으면 탑으로 가는 링크. 탑 탭과 숙련도 패널 위에는 늘 "🗼 탑 오르기 → 📖 비전서 → ⚜️ 스킬 강화" 흐름이 보이고, 강화한 스킬은 시전할 때 이름 옆에 `Lv`·별이 붙습니다.
- 규칙은 `src/tower.js`, 연출(층 오르기·추락·탑 캔버스 `#tc`)은 `src/world.js`의 `updateTower`·`drawTower`. 탑 안의 기사·몬스터는 하단바와 같은 눈금의 "층 좌표"에 있고 그릴 때만 그 층 높이로 옮겨서, 원정의 전투·스킬·이펙트 코드를 그대로 씁니다 (`fightTick`).

| 화염술사 | 화염 지팡이 | 불덩이가 맞은 자리 주변(40px)의 적도 50% 피해 |

- 몬스터는 기사의 사거리에 들어오면 기사에게 달려듭니다. 그래서 사거리가 긴 직업일수록 먼저 때릴 시간이 생깁니다.

### 스킬

1차 직업은 스킬 1종(Lv 25), 2차 직업은 2종(Lv 60 · Lv 70, 용기병의 용추락만 전직 즉시)이 있고, 2차 직업은 1차 스킬도 물려받아 최대 3종을 씁니다. 해금되면 교전 중 쿨타임이 찬 스킬부터 쓰고(레벨 높은 스킬 우선), 없으면 평타를 칩니다. 원정·결투·레이드에 모두 적용됩니다.

| 직업 | 스킬 |
|---|---|
| 검사 | 강철 베기 |
| 창기사 | 관통 찌르기 |
| 레인저 | 연사 |
| 성기사 | 심판의 일격 · 성역(보호막) |
| 검성 | 질풍난무 · 일섬(치명 확정) |
| 용기병 | 용추락 · 용의 숨결 |
| 할버디어 | 대회전 · 대지 가르기 |
| 저격수 | 헤드샷(치명 확정) · 철갑 관통탄 |
| 마궁수 | 유도 마탄 · 별빛 화살비 |

- 수치(해금 레벨·쿨타임·배율·타격 시점)는 `src/classes.js`의 `SKILLS`, 모션·이펙트·타격감(히트스톱·화면 번쩍임·컷인)은 `src/skills.js`의 `SKILL_FX`.
- 결투·레이드는 서버가 계산하므로 클라이언트가 프로필에 스킬 수치(`skills`)를 실어 보내고, 서버(`server/duel.js`)가 같은 규칙으로 씁니다. 재생할 때는 기록의 스킬 id 로 연출을 고릅니다.

#### 📖 스킬 숙련도 (Lv 1~30)

- 스킬마다 숙련도가 따로 있고, **📖 비전서로만** 경험치가 오릅니다 (써서는 오르지 않음). 1권 = 경험치 10, 레벨업에 `12 × Lv^1.2` (Lv1→2만 1권) — Lv10까지 약 77권, Lv20까지 376권, Lv30까지 **934권** (스킬 하나). 캠프 ⚜️ 전직 탭 위쪽에서 먹입니다.
- **쿨타임과 위력이 함께 성장한다**: 쿨타임은 `SKILLS`의 ×3.0(Lv1) → ×1.2(Lv30)로 줄고, 한 방 위력은 1.4배로 오릅니다 (`src/classes.js`의 `SKILL_CD_*`·`SKILL_DMG`). 다 키워도 쿨타임이 숙련도 도입 전보다 길어서, 스킬은 자주 쓰는 기술이 아니라 가끔 터지는 한 방입니다. 성장의 70%는 레벨마다, 30%는 Lv10·20·30을 넘는 순간 10%씩.
- **직업별 위력 보정**: 한 방 배율이 직업마다 Lv30 기준 ×1.70(용기병) ~ ×2.34(창기사). Lv30이면 모든 직업의 전체 DPS가 도입 전보다 +25%가 되도록 맞춘 값이라, 스킬 비중이 큰 직업일수록 낮습니다. 전체 DPS(도입 전 = 100%)는 Lv1 79~94% · Lv10 86~99% · Lv20 99~107% · Lv30 125%. 성역 보호막의 지속·감소·회복 수치는 그대로.
- **결투·레이드에도 그대로 적용** (프로필의 `cd`·`mult`에 반영). Lv80 실제 스탯 기준 같은 직업끼리 결투하면 Lv10이 Lv1을 74~91%, Lv30이 Lv20을 83~97% 이깁니다.
- **단계마다 기술이 진화한다** (`src/classes.js`의 `stages`·`stageName`·`stageDesc`, `skillAt`): Lv1 맨몸 기술(제자리·짧게) → ★ 무기 각성(멀리 닿음) → ★★ 전장이 바뀜(분신·지형·소환물) → ★★★ 궁극(거대 소환·시간 정지). **기술 이름도 진화**해서 이름 띠·숙련도 패널·돌파 안내에 새 이름이 뜹니다. 타격 배율 합은 원래와 같게 자동 보정(DPS 곡선 유지). 새 연출은 단계마다 전용으로 그린다 (`src/skills.js` 진화 연출 도구). 15개 스킬 모두 (검·창·활 계열).

- **1차 스킬 계승**: 2차 전직 뒤에도 1차 스킬을 숙련도 그대로 계속 씁니다 (`src/classes.js`의 `skillsOf` — 그 직업만의 스킬은 `classSkillsOf`). 그대로 얹으면 2차 직업 DPS 가 직업마다 +15~43%(Lv30)로 들쭉날쭉해서, 2차 직업에서 쓰는 계승 스킬은 위력에 `INHERIT_DMG`(직업별 ×0.35~0.77)를 곱해 전체 DPS 를 Lv1 +5% → Lv30 +10% 만큼만 올리도록 맞췄습니다. (예전엔 2차 전직 때 1차 스킬 숙련도를 비전서로 돌려줬기 때문에, 그때 전직한 기사의 1차 스킬은 Lv1부터 다시 키웁니다.) 숙련도 도입 시점에 모든 기사가 Lv1에서 시작했습니다.

#### 스킬·평타 모션 테스트 페이지 (개발용)

왼쪽에 기사, 오른쪽에 허수아비를 세워 두고 직업별 스킬이나 평타를 반복해서 보는 페이지입니다. 실제 게임 코드(`src/world.js`·`src/skills.js`)로 그리므로 스킬 수치·연출을 바꾼 뒤 바로 확인할 수 있습니다.

```bash
python3 -m http.server 8765
```

→ http://localhost:8765/dev/skills.html

- 모드: ✨ 스킬 / 🗡️ 평타만(공격 속도대로 계속 치기, 연속기 동작을 번갈아 또는 하나만 고정, 견습 기사 포함).
- 직업·스킬 선택, 자동 반복, 전 직업 순회, 스킬 사이 평타, 속도(×0.1~×1), 일시정지·한 프레임씩(스페이스·→ 키). 스킬이 끝나면 허수아비가 받은 실제 피해를 보여 줍니다.
- 게임 스크립트는 `index.html`의 목록을 읽어 같은 순서로 불러옵니다(`ui.js`·`net.js` 제외). 새 파일이 생겨도 페이지를 고칠 필요가 없습니다.
- 게임(`index.html`)은 이 페이지를 불러오지 않고, 앱 패키지(`package.json`의 `build.files`)에도 들어가지 않습니다. 웹에 올라가도 localhost 가 아니면 동작하지 않습니다.

| `render.yaml` | Render 배포 설정 (웹 서비스 + Postgres) |

### 직업 추가하기
- `src/classes.js`에서 `WEAPONS`에 무기를, `BODY`에 몸통 스프라이트를, `CLASSES`에 직업(스탯 보정 `mods`, 외형 `look`, 부모 `from`)을 추가하고 `CLASS_TREE`에 배치합니다.
- 전투 수치는 `core.js`의 `stats()` 한 곳에서 합칩니다.
- 기존 모션(`swing`·`dual`·`thrust`·`sweep`·원거리)에 없는 새 공격 방식이 필요하면 `world.js`의 `drawWeapon`과 `releaseAttack`에 추가합니다.

## 서버

로컬에서 띄우기 (DB 없이 `server/data/accounts.json`에 저장):

```
cd server && npm install && npm start
KB_SERVER=http://localhost:3000 KB_USER_DATA=/tmp/kb npm start
```

| API | 설명 |
|---|---|
| `GET /api/nickname?name=` | 닉네임 사용 가능 여부 |
| `POST /api/accounts` | `{ nickname, state?, profile? }` → `{ nickname, token }`. 중복이면 409 |
| `GET /api/me` · `PUT /api/me` | 내 세이브 읽기/쓰기 (`Authorization: Bearer <token>`) |
| `GET /api/ranking?sort=stage\|duel` | 상위 100명 + (인증 시) 내 순위 |
| `POST /api/duels` | `{ opponent }` → 결투 결과와 재생 기록 |

토큰(복구 코드)은 서버에 SHA-256 해시로만 저장됩니다.

### Render 배포 (DB는 Supabase)

1. **Supabase**에서 프로젝트를 만들고 Connect → **Session pooler** 연결 문자열(`postgresql://postgres.xxxx:[비밀번호]@aws-...pooler.supabase.com:5432/postgres`)을 복사합니다. Render는 IPv6를 못 쓰므로 Direct connection 대신 pooler 주소를 씁니다.
2. Render 대시보드 → **New → Blueprint** → 이 저장소를 선택하면 `render.yaml`대로 웹 서비스(`knight-bar`)가 만들어집니다.
3. `knight-bar` → **Environment**에서 `DATABASE_URL`에 1의 연결 문자열을 넣습니다. 테이블은 서버가 처음 뜰 때 자동으로 만듭니다.
4. 서비스 주소가 `https://knight-bar.onrender.com`이 아니면 `src/net.js`의 `DEFAULT_SERVER`를 바꾸거나 `KB_SERVER`로 지정합니다.

- 무료 웹 서비스는 15분간 요청이 없으면 잠들고, 첫 요청에 깨어나는 데 1분쯤 걸립니다. 클라이언트는 이를 감안해 계정·랭킹 요청을 최대 70초까지 기다립니다.
- Render 무료 웹 서비스의 디스크는 재시작마다 비워지므로, Render에서 `DATABASE_URL`이 없으면 서버는 파일 저장으로 넘어가지 않고 시작을 멈춥니다.
- Supabase 무료 프로젝트는 일정 기간 활동이 없으면 일시 중지될 수 있습니다(대시보드에서 다시 켤 수 있음).
